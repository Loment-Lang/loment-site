Loment 0.1.5.2 Beta 2 现已上线在线编译

参考编译器与 LVM 现在在浏览器标签页里运行。你可以先不安装工具链，直接编译、检查、构建 原生镜像，并查看 Loment 真正拥有的每一种中间形式。

这是 beta 通道，不是一次发布。在线编译运行的是快照，不是新标签；稳定通道仍停在 0.1.5.1。

编译器进了标签页

页面加载 Pyodide（编译成 WebAssembly 的 CPython），把参考编译器及其库写进虚拟文件系统。 一次运行用 tools/lomentc.py 编译源码，再在 LVM 里执行生成的 IR。没有内容 上传：源码、编译和输出都留在标签页里。 

module hello fn _start() {    let s: str = "hello from the browser\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

一个带显式 _start 的封闭程序。定义 fn main() 的程序会在内存里 得到一个合成的入口；源码不会被改写。

动作由语言决定，不照搬别的 playground

动作列表是 Loment 真正能暴露的面，所以没有 MIR、HIR 或文本汇编按钮。一共八个动作：

运行与检查

Run 编译并在 LVM 中执行。Check 在装载与检查后停止， 于是不必运行也能读诊断。

构建

通过 lomelf 产出原生镜像——Linux 的 ELF 或 Windows 的 PE——并提供下载。 镜像在标签页里构建，不由服务器编译。

LLVM IR 与 AST

编译器发出的文本 IR，以及解析后的模块：常量、结构体、枚举、能力与函数。这是编译器 作者最先读的两种形式。

Potato 与机器码

Potato 形式对象的 JSON，以及 ELF .text 段的十六进制清单。Potato 是 Loment 自己的序列化产物；机器码是随包链接器实际写下的东西。

Wasm

尚未实现。按钮说明计划并链接到设计记录，不会假装产出产物。

两个通道，两个不同的问题

Beta 跟随参考编译器最新的 main。今天标为 0.1.5.2.beta.2，并自动刷新，所以它回答“编译器现在做什么”。Stable 是 v0.1.5.1 标签上的参考编译器，回答“已发布的工具链做什么”。

两个通道各有独立的编译器、库与包存储。切换通道会保存当前源码并重新加载页面，因此为一个 通道写的程序不会在另一个通道下悄悄改变含义。

它还不能做什么

没有标准输入、文件系统与套接字；LVM 只认识运行器合成的那一个描述符。执行有步数上限， 永不结束的循环会被截断并报告。诊断是编译器自己的中文消息，页面不翻译它们。

自举编译器不在浏览器里：它发出 x86-64 ELF 与 PE，不发 WebAssembly。wasm32 后端的 设计在 docs/313，跟踪于 issue #1496；它落地后， 在线编译可以由用 Loment 写成的编译器驱动，而不必依赖 Python 参考实现。
