时间之桥

内存安全是一件极其应该认真对待的事情。Loment 的开发者一直在想办法，从各种路径去解决系统编程里最难的那个问题；答案现在以 LVM 与 LMS 的一次重大更新出现。这是 0.1.6 的第二篇开发笔记。

这篇笔记写的是审阅中的工作。它讲的三个改动都还开着，没有合入；稳定版仍是 0.1.5.1。已经在 main 上的部分会写明。

内存就是全部题目

一个指针活得比它的对象久，一个下标越过了边界，一代对象没被检查，程序读到或写到不属于它的东西。这个领域背着这个问题已经几十年。Loment 的答案从来不是单一机制：LMS 分级检查，能力域划定权限，借用检查器推理生命周期，GC 梯子选择回收方式，LSPE 审计结果。LVM 是这一切最终跑在其上的引擎。

一份外部提案 PANGU Ω 带着七层架构到来。我们把它和树里的东西对了一遍：五层已经有对应物，真正缺的是三件。那三件变成了文档，文档变成了下面的改动。

LMS 长出 fault ABI

原生的 g1 溢出检查过去以 __loment_abort 收尾，它降成 ud2——SIGILL，退出码 132，工具什么也读不到。在 choose lms_pangu_true 下，它改成调用 __loment_fault(1)，退出 101；另外两类故障是 102 和 103。每个故障都用 fn:blk#idx 点名站点，与 LVM 基质报告的坐标相同。一次普查走遍每个 guest 的 load、store 与原子读改写，把坐标写下来。自举实现发出相同的故障文本，种子重新生成，两套实现的故障段逐字节相同。

这次工作还揪出一个真 bug：IR 缓存键把用户开关漏在源摘要之外，改一行 choose 可能拿回旧产物。已修。

LVM 变成一台机器

LVM-A 是一台有六个原语的抽象机：站点、能力检查、代检查、故障、检查点、恢复。它可以在四种基质上实现：sw_cap、sw_tag、hw_cap、hw_tag。第一档已经落地：对象表带 base、limit、generation、alive 与 kind；能力沿 SSA 值、GEP 基、形参、存储的指针、phi 与 inttoptr 传播；每个 guest load 与 store 之前都做检查。失败退出 101、102 或 103，并点名站点。默认基质是 none，所以普通程序发出的东西和以前一样。

边界和功能一样写清楚：地址被 as u64 洗过之后能力会丢；地址复用后的悬垂暂时抓不住，因为对象代必须跟着指针走。

两个解释器都能读的快照

检查点过去是内部细节，现在是一种格式：两个解释器写出相同的 LVMC 字节——4 MiB 内存、32768 字节的帧、深度 32——并且能恢复彼此的快照。程序按名字携带，不按块号，因为两个解析器给块编号的方式不同。命令行也是快照的一部分，恢复时可以交给它另一组宿主参数。

修了一个恢复 bug：某个基址写入时是字节偏移，读出来却当字偏移，于是恢复后的第一次返回把整张对象表都退掉了。封印是旁挂文件，不是编译器输出：它携带产物哈希、逐站点台账、带保证与假设的基质档案、零 import 验证器，以及同产物创世衰减。schema 2 还带两个解释器各自的字节与行数价格，以及一份预算——8000 行、320 KiB，今天实测 7,936 行。

故障变得可读

程序死掉时，有意思的部分通常不是那个信号。LVM 故障现在会在稳定的第一行之后打印一个 Lomenterr 形状的块：对象表项、偏移与越界量、退役的代、站点、建议；llvm.trap 也一样。原生侧分几级：ptrace 报告器给出信号、si_code、地址、PC、RSP 与可选源码行；lomelf --fault-report 让产物自己在备用栈上报告，带读/写方向、地址、PC/RSP、站点与栈溢出提示；自举链接器产出逐字节相同的 ELF。还有一小步可选的：--fault-heal N 把 1 MiB 以下未映射的页零映射，再回到同一条指令，受预算限制；页 0 默认仍是致命的。

做镜像时掉出两个 bug：fn main 入口被发成 call i32 @main，少了括号，那条路从没编译过；函数序言里的故障会被算到上一个函数的最后一个站点。现在站点带着降级后的代码长度，查找是半开区间。

公证人

审计只有在审计者站在被审计物之外时才值钱。LNotary 是一个独立的产物审计器，只读 Potato，不导入工具链的任何部分——不导入编译器、不导入 Potato 模块、不导入 LSPE。它核对 systems 表、GC 梯子、LMS 等级与预算、LSPE 台账与开关的自洽；派生一个旁挂的 lawspace，带维度、法则与内容寻址的封印；核对站点表并绑进封印；还能核对同产物派生链，能力、预算与深度只许收缩。它只在启用了 LVM 的产物上生效，否则按名字说明原因。

时间之桥

下面是值得这个名字的部分。六个原语在每种基质上都是同一台抽象机。封印记录产物是为哪种基质构建的，连同它的保证与假设。唯一硬判据是 B5：同一份 IR 按 sw_cap 封印、按 hw_cap 封印，字节码哈希相同。这就是让硬件换代变成重新封印、而不是重新编译的东西。

当前硅片上，六个硬件原语有五个缺失或只有一半。LVM 档是这门语言不等下一代硬件就翻过这堵墙的方式：指令级标记在机器内部消失，两个边界检查从墙变成成本，写权限变成一条指令，精确检查点变得可行，不可核 ISA 那堵墙下移一层，公理变成“CPU 正确地执行解释器”。信任链四层：字节码与封印、LVM-A 模型、两个解释器、宿主 ISA。

更新路径

还有一个开着的改动属于这个故事。热更新过去只替换正在跑的语言服务器映像；bin/ 里的链接器、编译器、CLI 与构建工具从来没有到达安装。新的载荷带上每个工具，从发布种子上的投影树构建，打包并签名。更新器用随工具链发布的标准库验证原始 Ed25519 签名与每个 SHA-512 摘要，写进非活动的那一代，然后才切换 current。支持 check、rollback 与 status。一个原装的 0.1.5.1 安装会得到一次性的 bootstrap，因为它没有更新器，也没有可作起点的固定公钥。

还没做什么

这三个改动都开着。sw_tag 只在参考解释器里。跨实现恢复只在孪生夹具上证明过，没有真实文件 I/O，也没有在 phi 中间恢复。自举侧的能力精度是按地址重建的。原生诊断只支持 ELF，默认关闭；Windows PE 是后面的阶段，报告在一个小程序上会让产物大约变成 3.3 倍。修复只覆盖 Linux 下 1 MiB 以下的 SIGSEGV/SEGV_MAPERR，并且受预算限制。默认构建发出的东西和以前一样。

在 2027 年的开始，你将能够使用这座时间之桥。

下一篇笔记会说哪些合入了。— Loment Dev Fujo
