博客 · 2026-11-11

2026年的终点

我正在把 2026 的最后几周花在一张很短的清单上：0.1.5.2 正式版、0.1.5.3 的首个测试版本、 一个用起来像工具的在线编译，以及生命周期与 GC 时机的又一轮。下面是这张清单的长版本。

这是我正在执行的计划。今天稳定通道仍是 0.1.5.1。我有顺序，没有日期。

2026 落到了哪里

2026 把项目从 0.1.4 推到 0.1.5.1。表层语法现在有三档：Tur 2026.1 已冻结， Tur 2026.2 在十一月封版，Tur 2026.3 是我还在动的那一档。一个文件可以钉住自己写给 哪一版读。这就是整件事的用处。

域变成了走进去、离开的块：进去时域开始，出来时结束。十八种域全部落地， domain:for 能遍历位置，树与图的边也成了语法（child_of、 couple、mutex）。LSPE v2 以四件套到来：质疑器（E1–E8）、 反问器（Q001–Q013）、LSPC 预检表，以及每个站点带证明哈希、带 .lspe 旁挂的台账。

借用生命周期在没有生命周期语法的情况下落地。&T 与 &mut T 在形参、返回、结构体字段与泛型实参里都是一等类型；从 tur2026.3 起 lifetime_auto 是默认，常见情形不需要标注。 自举编译器在 2026-11-08 跟上：E041 现在只在区域不成立时出现。lgc 给收集器一个时钟：lgc start(10ms) { … } 打开带协作式预算的收集窗口， lgc end; 暂停；no_gc 加 lgc 是 E039，因为 没有收集器可控制。

store 到了 13 个包、332 个模块、2791 个公开函数。我补上了 ChaCha20、Poly1305、 AEAD、AES-CTR/GCM、x25519 与 ed25519，带 SCM_RIGHTS 的 AF_UNIX， TLS 1.3 客户端核心，事件循环、原子文件操作、有界 channel、任务队列、小型 HTTP 服务器，以及一份 Windows 声明面。在线编译把参考编译器与 LVM 放进浏览器标签页； Java 库不需要 JVM 就能调用；热更新成了发布形态的东西；wasm32 成了一份设计记录。

开着的清单在最后一节，我把它留着。

最后一段的顺序

顺序很短。先让 0.1.5.2 成为正式版。beta 线已经有域、LSPE v2、 生命周期维度、扩充后的 store 与在线编译快照。升正式版的那一周，通道、产物、签名与 说明必须彼此对齐。两套实现读同一套表层、判据全绿，我才会移动稳定通道。

然后 0.1.5.3 以首个测试版本开版。我想在下一条线还热的时候让它跑起来。 测试版本是那些仍是设计的东西第一次拿到可执行形状的地方。我保留这个顺序，因为先有稳定 的地板，下一个版本才好评判。

“正式版”可能最有用的意思很窄：一个标签、签名产物、Stable 能指向的通道，以及一份 写明缺什么的说明。有些开着的设计项在它之后仍然开着。清单留在最后一节，直到对应的判据 出现。

同一段时间里的三条线

在线编译

我正在把接下来的几周花在在线编译上，因为它是大多数人第一次见到这个编译器的地方。 我想要更快的首次加载与更小的快照；一个能保持行号、语法、诊断与选区正确的编辑器； 更清楚的 Run、Check、Build、IR、AST、Potato 与机器码动作；以及能在手机上用的布局。 Beta 继续跟 main；Stable 继续指向已发布的标签。不上传源码，也不长服务器。

生命周期

我正在把 lifetime_manual 从 &a T 标记往外扩，把借用 作为泛型实参带到两套实现，并让诊断说出源、行号与路径。可能零标注的情形仍是默认； 显式的情形应当少而清楚。

GC 时机

我正在收紧 lgc 的预算语义，在四层梯下量收集器，并把每一档在负载下承诺 什么写下来。预算管的是开始一次收集，不抢占已经在跑的收集。no_gc 仍是 真模式，no_gc 加 lgc 仍是 E039。

这里的“终点”是什么意思

学年因为有日历才以期末考试结束。语言结束的方式不一样。我封版的标准是表层不再动、 判据全绿。十二月适合停下来看一眼，不适合拿来宣布工作结束。

可能诚实的年终陈述比发布会小：我可以在一页里把项目说清楚，而不编造任何东西。 这是我想给下一年定的门槛。

仍然开着的

清单还在这里。lifetime_manual 需要更宽的标注面。扩展域与图模型的实体 部分仍是设计。wasm32 后端是一份设计记录，我还没法把它当后端用。store 的平台与协议 边缘是边界；Windows 模块在等 PE FFI。五个 store 缺口仍然只是一个分支。它们都没有 日期。

上一篇测试版本笔记在这里；在线编译在 这里。其余都在仓库里。
