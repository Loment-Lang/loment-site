发布

发布历程

从最早的 Loment 到此刻发布的那一版。每一条都说明那一版是为了什么 —— 以及 它的记录在哪里，因为最早的那些版本是从另一个仓库发布的，而这个仓库并不带着它们的标签。

下载 入门

这是本站唯一一页写出具体版本号的页面。别处下载链接一律写 releases/latest，因为写在页面上的版本号是一个会过期的说法。而这里 版本本身就是主题，所以它们被写出来，每一个都指向当时真正发布的东西。 其中没有任何一条是对尚未发布的版本所作的承诺。

在这个仓库之前

最早六个版本出自这个项目之前的那个仓库。它们的标签不在这个仓库里，日期也不在，所以 下面给出的是这条线的形状，而不是一份带日期的记录 —— 而且这里没有一处链接，因为没有 什么可链。

0.1.1 —— 第一个 Loment

Rust 语法的严格子集。那是最初的约束，而不是一种风格：这门语言由 Rust 已经定下来的东西来定义，所以几乎没有什么可争的，需要的只是把编译器建起来。 它如今不再声称是子集 — 重叠面还在，只是当语法面长过它之后，那个说法被撤掉了。

0.1.2 Alpha —— 第一次自举

这门语言开始用自身来写。它买到的不是优雅：一个用它自己所编译的语言写成的编译器， 是找出这门语言表达不了什么的唯一办法。

0.1.2 pre1 —— 修补

第一次自举暴露出来的那些问题。预发布正是这类东西该发生的地方。

0.1.2 pre2 —— 至今仍立着的地基

此后每一次发布都建在它之上的自举地基：一个从提交进仓库的种子重建自身的编译器， 以及一条"重建出来的种子等于它出发时的那个"的判据。

0.1.3 Alpha —— 多语法这个想法到来

第一个可以把另一种语言的源码当作 Loment 来读的版本。语义永远是这门语言的，借来的 只是拼写。它是这个项目的立论，而不是后来加上去的一个功能，所以它列在这里，而不列 在"还有什么不同"下面。

0.1.3.4 Alpha —— 闭环

四个阶段 —— 词法分析器、解析器、检查器和代码生成器 —— 全部用 Loment 写成，产物 到达一个三阶段的定点。这是从上一个仓库发布的最后一个版本，也是此后每一个版本拿来 对照的那一版：它是语言与编译器不再需要一个宿主来定义自己的那个发布。

来自这个仓库

在这个仓库里发布过、并且排在此刻这一版之前的三版。每一版都只占一行，而不是一节， 理由是一份记录应该给出的：细节在它链去的那张发布页上，而一份不断完整生长下去的历史 就不再是历史，而是档案的第二份副本。

0.1.4 Pre —— 第一个装得上的 Loment

2026-09-22。它被当作预发布挂出来只有一个原因：让"这个仓库是有版本 的"不再是一句声称，而变成一件你看得见的事实。有一处制作上的细节留到了今天 —— 标签 指向的 commit 比归档包所构建自的那个更早，所以 GitHub 自动生成的源码归档包，是那次 构建之前的树。

0.1.4 —— 可用

2026-09-23。主题是可用，而不是往里塞更多东西：语法面完全 没有变，力气都花在把解释器最后一点从必经之路上拿掉。它的 Windows 安装器在那些把 Windows 配置成不搜索当前目录的机器上什么也不做；要这一版请从 zip 安装。

0.1.4.5 —— 回收，以及一个成为保证的运行时

2026-10-13。四级回收阶梯，带一个自适应的一半和一个分代的一半； no_runtime 从声明变成了保证；两个目标上都有网络；第五个维度 vm 到来，而它的发行闸是关着的。同一天的一个补丁只改了 Windows 安装器。

0.1.4.6 —— 闸门落下

2026-10-17。四样早就建好、却一直被挡在发布之外的东西，在这一版里一起 到手：编译器旁边的一层解释器、libc 与 LibL，以及 vm 这个维度。剩下的部分 是这个项目至今最大的一轮缺陷清扫；仓库里那些 issue 编号大多出自它。

新增

  1. LVM —— 解释器层，T0 到 T3。它读的是链接器读的同一份中间形式，所以 一个程序永远不会多出第二个真源。T0 是那份形式的第四个读者；T1 记下一份反馈剖面， 而不改动一个字节的输出；T2 把指令解码搬出执行循环，在语料上达到 T0 的 6.1×，输出逐字节相同；紧凑形让同一个单元从 375.9 KB 变成 107.0 KB；T3 加上带守卫的特化与去优化。 这一版接受 choose vm —— 0.1.4.5 在发布构建里拒绝它， 那道闸是在这里打开的。这不意味着：解释器是仓库里的 tools/lvm.py 那一族，包里并不带它，而且这个维度还不改变编译器发出的 东西。这一行是一条声明，不是保证 —— 与 no_runtime 在 0.1.4.5 里的分量相同。
  2. libc 与 LibL。发布构建链上真正的 libc.so.6 并跑通到底。 LibL 那一面 —— fopen/fread/fwrite/ fseek、其余 printf 格式、作为内建堆拼写的 malloc/calloc —— 是拿系统里真的 glibc 判的。0.1.4.5 对 use libl 和对 libc 的锁已经开了。
  3. 线程。语言里的 thread_spawn，加上一个 os/thread 库，它的系统调用号是从头文件里读的，不是背下来的。
  4. 四个随包发出的库，每一个都拿真实现判过。os —— 五个 模块对着同一个 Linux 环境里的 CPython；internet —— 七个模块对着真的 解析器与服务器。
  5. LMS 第 1 级 —— 收集器之外的第二套内存架构：它的检查器 （E028/E029）与它的第 3 级入口，两个实现都有。
  6. 一道能看见运行时的闸，以及分发。104 条需要产出二进制的判据现在在 Linux runner 上原生运行，而不是跳过；没跑过的判据不再算作通过。四个宿主上的只读 镜像；一份简体中文 README；VS Code 扩展上了 Marketplace。

修复

  1. 回收。清扫器不再对每个被释放的块清掉四个标记字节 —— 那曾让活块在 垃圾旁边被一并收走；free 检查归属，拒绝二次释放；块内精确是逐站点的槽 掩码；白名单系统调用的实参算作借出；一次收集不再清空空闲链表；收集触发挂在"字节被 要"的地方，计的是分配器真正吃掉的数量；复用的块保留它记录下来的尺寸；被提升的缓冲区 的字进入根扫描；L2 的纪元在下一个同名 let 处停下，于是两个相邻的循环 不再互相挡。
  2. 那些曾经静默或报错的诊断。语句开头的 @、二进制字面量 与"走到函数末尾"规则，都按参考实现的方式拒绝；未知类型是 E030 而不是 E002；七处 曾经静默、报错或致命的场合现在说出与参考实现相同的话；同一个程序在每一门表层语法里 算出同样的数；use std 不再崩溃；格式化器保留注释，也把声明修饰符留在 声明那一行。
  3. 发射器拒绝它表达不了的东西。混合宽度运算、自举编译器里的 bool != bool、11 个以上参数、最后一个字段没有尾逗号的结构体，以及放不进 其声明类型的整数字面量，都成为错误，而不是非法 IR。
  4. 运行时与命令行。数组下标与算术都做了检查；除零是一个带消息的陷阱； 默认档的拒绝报出正确的设置名；let x = 1;、let a: f64、 一个裸的 return;、brk 用的编译器自己的堆、250 项表达式与 400 层嵌套块，都被诊断而不是崩溃；Windows 出的是 PE 而不是 ELF； loment check 不再为一个建不出来的文件以 0 退出。
  5. 链接器。负下标做符号扩展；自举链接器读得懂 64 位全局量与多行 case 表。
