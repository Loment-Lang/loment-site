发布

发布历程

从最早的 Loment 到此刻发布的那一版。每一条都说明那一版是为了什么 —— 以及 它的记录在哪里，因为最早的那些版本是从另一个仓库发布的，而这个仓库并不带着它们的标签。

下载 入门

这是本站唯一一页写出具体版本号的页面。别处下载链接一律写 releases/latest，因为写在页面上的版本号是一个会过期的说法。而这里 版本本身就是主题，所以它们被写出来，每一个都指向当时真正发布的东西。 其中没有任何一条是对尚未发布的版本所作的承诺。

在这个仓库之前

最早六个版本出自这个项目之前的那个仓库。它们的标签不在这个仓库里，日期也不在，所以 下面给出的是这条线的形状，而不是一份带日期的记录 —— 而且这里没有一处链接，因为没有 什么可链。

0.1.1 —— 第一个 Loment

Rust 语法的严格子集。那是最初的约束，而不是一种风格：这门语言由 Rust 已经定下来的东西来定义，所以几乎没有什么可争的，需要的只是把编译器建起来。 它如今不再声称是子集 — 重叠面还在，只是当语法面长过它之后，那个说法被撤掉了。

0.1.2 Alpha —— 第一次自举

这门语言开始用自身来写。它买到的不是优雅：一个用它自己所编译的语言写成的编译器， 是找出这门语言表达不了什么的唯一办法。

0.1.2 pre1 —— 修补

第一次自举暴露出来的那些问题。预发布正是这类东西该发生的地方。

0.1.2 pre2 —— 至今仍立着的地基

此后每一次发布都建在它之上的自举地基：一个从提交进仓库的种子重建自身的编译器， 以及一条"重建出来的种子等于它出发时的那个"的判据。

0.1.3 Alpha —— 多语法这个想法到来

第一个可以把另一种语言的源码当作 Loment 来读的版本。语义永远是这门语言的，借来的 只是拼写。它是这个项目的立论，而不是后来加上去的一个功能，所以它列在这里，而不列 在"还有什么不同"下面。

0.1.3.4 Alpha —— 闭环

四个阶段 —— 词法分析器、解析器、检查器和代码生成器 —— 全部用 Loment 写成，产物 到达一个三阶段的定点。这是从上一个仓库发布的最后一个版本，也是此后每一个版本拿来 对照的那一版：它是语言与编译器不再需要一个宿主来定义自己的那个发布。

来自这个仓库

在这个仓库里发布过、并且排在此刻这一版之前的那几版。每一版都只占一行，而不是一节， 理由是一份记录应该给出的：细节在它链去的那张发布页上，而一份不断完整生长下去的历史 就不再是历史，而是档案的第二份副本。

0.1.4 Pre —— 第一个装得上的 Loment

2026-09-22。它被当作预发布挂出来只有一个原因：让"这个仓库是有版本 的"不再是一句声称，而变成一件你看得见的事实。有一处制作上的细节留到了今天 —— 标签 指向的 commit 比归档包所构建自的那个更早，所以 GitHub 自动生成的源码归档包，是那次 构建之前的树。

0.1.4 —— 可用

2026-09-23。主题是可用，而不是往里塞更多东西：语法面完全 没有变，力气都花在把解释器最后一点从必经之路上拿掉。它的 Windows 安装器在那些把 Windows 配置成不搜索当前目录的机器上什么也不做；要这一版请从 zip 安装。

0.1.4.5 —— 回收，以及一个成为保证的运行时

2026-10-13。四级回收阶梯，带一个自适应的一半和一个分代的一半； no_runtime 从声明变成了保证；两个目标上都有网络；第五个维度 vm 到来，而它的发行闸是关着的。同一天的一个补丁只改了 Windows 安装器。

0.1.4.6 —— 闸门落下

2026-10-17。四件建好了、却一直被挡在发行版之外的东西同时变得可达： 编译器旁边的解释器档、libc 与 LibL、以及 vm 这一维。其余是 0.1.4.7 之前最大的一次缺陷清扫。

0.1.4.7 —— 库成为孪生

2026-10-18。一次缺陷发布，而头条不是一个功能：包里随附的每一个库， 在两个实现里都编出逐字节相同的 IR —— 155 个模块，没有一个被跳过。为了走到这里翻出来 的是一批静默的状态 bug，而不是它们从外面看起来的那种「分歧」。

0.1.5 —— 矩阵，以及最后一道闸打开

2026-10-20。这一版讲的是把承诺变成你能查看的产物。choose 成了一个七维矩阵，其中每一个合法的格子都由两个实现各编一遍、再逐字节 比对；安全内存管理器与审计账本发布；解释器随工具链一起发布；而最后一道发行闸 —— 那道把 审计子系统挡在发布构建之外的闸 —— 已经不在了。

新增

  1. 七个设置，每一个合法组合都被编译。mode、gc、 runtime、port、vm、lms 与 lspe；产物层面的几行，判在链接后的映像上，而不只是判在 IR 上（17 条 判据）。
  2. hosted 那一层被点名了。std 可以带 hosted 的名字 （libc、文件系统、线程、时间、网络），no_std 不可以； std + hosted 链上真正的 libc.so.6 并跑起来； 两个前端都拒绝 no_std + hosted；而 IR 自己声明了那一行， 所以链接器核对的是它没有写下的那条声称。
  3. no_gc 是一条被核对的声称。产物写着「没有收集器」，而 如果映像里有一个收集器，链接器就让这条声称失败。
  4. 安全内存管理器发布。七个级别 —— 编译期检查、内存映射图、守卫、 拒绝器、崩溃器、进程外重启器，以及一个最低限度的底 —— 默认是 lms_full， 设置上有四档。
  5. 审计子系统发布。LSPE 是第七个设置：记录每个判断依据什么的账本、 需要判断的站点的清点、带有局部与过程间引擎的义务系统，以及 lspe pass "reason" { … }，作为一种会被计数、按词法生效的绕过。发布构建 接受它。
  6. 这道闸说出它跳过了什么。已知红的名单点名的是判据，而不是一整个套件； 预算是对着基线分支核的，所以一次改动不能降低一条地板、也不能新增一条跳过；容量扫描器 覆盖整棵树里的字面量边界与定长数组；而自举的根带着一份重建可以证伪的来源记录。
  7. 解释器随工具链一起发布。T0 到 T3、紧凑序列化形式、一份缓存的产物与 一条性能上限，全都对着记录在案的账本量过。
  8. 随包链接器在 libc 需要的那些部分上与参考一致。位置无关代码、TLS 重定位与弱对象把 C 那一面收尾；IFUNC 与 STT_NOTYPE 导入、没有 SONAME 的 共享对象以及 PT_GNU_RELRO 把它补齐。
  9. 安全，按行为来说。free 在复用之前把那块载荷擦干净；HTTP 请求构造器拒绝 CR、LF 与 NUL；安装器核对它复制的每一个文件，并且用绝对路径调用 PowerShell；而发布会对 SHA256SUMS 发布一份分离的签名，放在它所描述的那些 归档包之外。

修复

  1. 自举编译器里互相覆盖的状态槽。一个 match 臂的标签覆盖了 收集器档位的标志，而发射器的诊断槽又覆盖了线程创建的标志 —— 在一条线程探针上表现为 一条假的「超过 20 个参数」错误。两者现在各有自己的槽，并由判据钉住。
  2. 固定容量的表越界时不是拒绝，而是被写坏。检查器的名字环境没有边界 （2048 字节、256 条）—— 一个函数里 515 个 let 在 Linux 上段错误，在 Windows 上则静默地写了出去。它现在容纳 4096 条，并在到达上限时停下；发射器的几张表 加上了守卫和点名的诊断。
  3. 崩溃换成了诊断。自举词法分析器不再读过 token 缓冲区的末尾，解析器的 嵌套上限是对 ( [ { 加一元链的一趟扫描，而准入 工具对过大的输入报错，而不是把它截断。
  4. 点错了东西的链接器失败。有两条消息还在描述已经不存在的闸；输入缓冲区 长到 6 MiB；而归档表、重定位表与导入表是被固定住，而不是被加宽。
  5. 前端与 CLI 上的沉默。六处检查器修复、十个用户看得见的 CLI 情形、 一趟 C 翻译，以及十三处渲染器/链接器修复 —— 每一处都是输入可能一声不响地丢掉的地方。
  6. 两个格式化器现在对多行 || 表达式里的注释达成一致。 有一条判据把语料里的每个文件逐字节比一遍。
  7. lompi 的网络层就是 internet 包。手写的那些 HTTP 名字 没有了；注册表索引在带外被钉住；而一个「拉取完成」的标记由它的消费者核对。
  8. 里程碑里 134 条带 bug 标签的 issue 全部关闭，而每一处改变了行为的 修复都带着一条判据：修之前是红的，修之后是绿的。名单连同点名每一条的那个 issue，在 里程碑页面上。

这一版没有

审计子系统在包里，但还没有从包里拆出去：打包的拆分是 0.1.5.1 的事。 no_std 的完整能力链报告是一条加载器规则，仍然留在 #536。choose vm 仍然不改变编译器发出的东西 —— 解释器是你能运行的一个程序，而不是一种编译器模式。而 审计账本还没有吃进内存管理器的守卫检查；那条接缝写在 docs/270 里。
