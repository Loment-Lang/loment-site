可以走进去的域、完整 LSPE，以及下一步的生命周期

这周有三件事值得写下来：域从文件顶部的一行声明变成了能走进去的块，十八种域全部落地， LSPE 的四件套已经在 0.1.5.2 beta 里，接下来的工作是借用生命周期。这是人话版。

这是一篇进度笔记，不是发布公告。Beta 是 main 的快照； 稳定通道仍是 0.1.5.1。写成“接下来”的内容是方向，不是日期。

域现在是代码里的一块地方

以前的域是一条声明。你在文件顶部写一次 capability blk_write : disk[0..4]，然后在函数里写 guard blk_write(slot)。它告诉读者这段代码想做什么，编译器基本选择相信 那一行。新的域是一个块：走进去，域开始；走出去，域结束。值会说明自己住在哪个空间， 访问这样的值会自动经过守卫。

写成 domain buf : disk[0..63] consumed(1) { … }，再把值声明成 a: [u32; 64] in disk，块里的 a[i] 就会在取址之前检查 buf(i)。显式的 guard buf(i) 仍然可用；块之外再写 guard buf(i) 是编译错误，因为 buf 已经不存在了。

重点不在语法更好看。域现在有了位置，也有了寿命。有状态的域把状态分配在当前栈帧里， 所以每次循环、每次递归都会拿到一个新实例，不再共用一张全局表。

诚实的边界。空间标记不会跟着调用走；被调函数看到的是普通类型。 自动守卫只覆盖直接下标，不覆盖 ptr_add。块域还没有写进 Potato 形式对象。

十八种域，三个问题

每个域都在回答三个问题：下标可以在哪里（形状），它标记的是允许还是禁止（极性）， 答案什么时候会变（时间律）。原来的十种覆盖了常见情况；这周另外八种也落地了。 十八种现在全部随包发布，两个编译器为每一种发出的 IR 都逐字节相同。

用日常的话说：区间说明“在哪里”。consumed(1) 说明每个位置在每个实例里 只能用一次。cyclic(P) 会绕圈。generational(N) 每 N 个 tick 翻转一次答案。adaptive 用质量字节收缩允许的范围。reachable(K) 把一个位置预留 K 个 tick，并等待一次释放。subject、witnessed 和 flow 还要第二个实参：位掩码、票据或打包的边。

边界也要说清楚。subject 与 witnessed 的票据由调用方提供； 语言只数使用次数，没法让票据不可伪造——那需要线性值。flow 是一段打包的 边范围，不是任意边集。两个编译器在 IR 上一致，也都写清自己不管什么。

域可以走了

以前域只是拿来守卫的；现在它可以被遍历。domain:for i { … } 走过当前域的 位置；domain:for i in buf step 2 点名一个域并跳着走； domain:for i, j in A, B 并行走过两个同形状的域；step -N 反向走。

循环头只放一次守卫，每条回边推进一次虚拟钟。完全不碰域的程序一个字节都不会变。 想自己驱动时钟，就写 choose domain_clock_explicit 关掉自动 tick。

树的边和图的边也进了语法。child_of 声明父域；couple A, B 让两个域作为同一个续期单位，守卫任一边都会静默检查另一边；mutex A, B 是编译期承诺：两个有限、非 danger 的形状永不重叠。 tools/loment_geometry.py 会把树、图和位置轴打印成确定性的 JSON。

仍是设计的部分：→ 委托、≺ 时序、 × 排他、扩展域、工具域，以及图的立体部分。页面和编译器都会直说， 不假装地图已经画完。

LSPE 在 0.1.5.2 beta 里完整了

LSPE 是审计层：它记录每个判断到底建立在什么之上。0.1.5.2 这条线有四件，现在四件都在 beta 编译器里。

质疑器有八个引擎（E1–E8）：循环、按类型与替换键控的良构性、永不解除的差分判断， 以及从测试树生成的探针注册表。反问器有固定问题模板（Q001–Q013）和回答通道：默认 允许但打标签，defer 与 refuse 是显式动作，strict 模式会把 没回答的问题变成错误。LSPC 是起飞前检查单——十二个族乘五列，有 full、quiet、strict、off 四种模式； loment lspc check 只读前端，不写任何东西。

台账保留推导树、每个站点的证明哈希、.lspe 旁边的文件，以及 I1–I5 五条 不变量。loment lspe why 和 loment lspe verify 读它。它现在 在 Beta 通道里；在线编译跑的就是这份快照，所以 Run、Check、Build 用的都是同一个 编译器。在线编译没有加 LSPE 按钮，因为台账是命令行产物，不是一个文本框上的动作。

下一步是生命周期

下一条线是借用生命周期。它在文件头选择性开启：choose lifetime_true。 目标是 Rust 的保证，不要 Rust 的标注噪音：没有 'a，没有 <'a>，没有 where。&T 与 &mut T 在字段、返回值和泛型实参里成为一等类型；编译器为每个借用 推断一个区域，并检查它不会比来源活得更久。

省略规则故意做得很激进。一个借用入参，所有借用出参都借自它。多个借用入参、一个出参， 取最短的那个——所以 fn min(a: &[u32], b: &[u32]) -> &[u32] 一个标注都不用写。方法默认借自 self。只有返回值必须绑到某个特定入参时， 才写那个参数的名字，例如 -> &a [u32]。

检查器遵循 LSPE 的温柔哲学：它点名来源——哪个变量、哪一行——并解释路径，不会只丢下 一句“生命周期错误”让你自己猜。严格模式存在，但默认不开。生命周期域系列延续同一个 想法：一个区域就是一块有入口、有出口、有“什么可以穿过”的规则的地方，检查器问的是 和 LSPE 同一类问题。

这是进行中的工作，不是已发布的功能。伞是 #1240，设计在 docs/299； 子任务一个一个落。这里没有日期。
