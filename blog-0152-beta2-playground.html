Loment 0.1.5.2 Beta 2 is now on the Playground

The reference compiler and the LVM now run inside the browser tab. You can compile, check, build native images and read every intermediate form Loment actually has, without installing the toolchain first.

This is a beta channel; it is not a release. The Playground runs a snapshot, not a new tag; the stable channel stays on 0.1.5.1.

The compiler moved into the tab

The page loads Pyodide, a CPython build compiled to WebAssembly, and writes the reference compiler and its libraries into a virtual file system. A run compiles the source with tools/lomentc.py, then executes the generated IR in the LVM. Nothing is uploaded: the source, the compilation and the output stay in the tab. 

module hello fn _start() {    let s: str = "hello from the browser\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

A sealed program with an explicit _start. A program that defines fn main() instead gets a synthesised entry point in memory; the source is not rewritten.

Actions come from the language, not from another playground

The action list is what Loment can actually expose, which is why there is no MIR, HIR or textual assembly button. There are eight actions:

Run and Check

Run compiles and executes in the LVM. Check stops after loading and checking, so a diagnostic can be read without running anything.

Build

Produces a native image through lomelf, an ELF for Linux or a PE for Windows, and offers it as a download. The image is built in the tab; it is not compiled by a server.

LLVM IR and AST

The textual IR the compiler emits, and the parsed module: constants, structs, enums, capabilities and functions. These are the two forms a compiler writer reads first.

Potato and Machine code

The Potato form object as JSON, and the hexadecimal listing of the ELF .text section. Potato is Loment's own serialised artifact; the machine code is what the bundled linker actually wrote.

Wasm

Not implemented yet. The button states the plan and links to the design record rather than pretending to produce an artifact.

Two channels, two different questions

Beta follows the latest main of the reference compiler. It is labelled 0.1.5.2.beta.2 today and is refreshed automatically, so it answers “what does the compiler do right now”. Stable is the reference compiler from the v0.1.5.1 tag, and answers “what does the released toolchain do”.

The two channels keep separate compilers, libraries and package stores. Switching a channel saves the current source and reloads the page, so a program written against one does not silently change meaning under the other.

What it cannot do yet

There is no standard input, no file system and no sockets; the LVM only knows the one descriptor the runner synthesises. Execution has a step limit, so a loop that never ends is cut off and reported. Diagnostics are the compiler's own Chinese messages, and the page does not translate them.

The self-hosted compiler is not in the browser: it emits x86-64 ELF and PE, not WebAssembly. The wasm32 backend is designed in docs/313 and tracked as issue #1496; when it lands, the Playground can be driven by the compiler written in Loment rather than by the Python reference implementation.
