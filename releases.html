Releases

Release history

From the first Loment to the one shipping now. Each entry says what that version was for — and where the record of it lives, because the earliest ones were released from a different repository and this one does not carry their tags.

Download Get started

This is the one page on this site that names versions. Everywhere else the download link says releases/latest, because a version number written on a page is a fact with an expiry date. Here the versions are the subject, so they are named and each one points at what was actually published. None of it is a promise about a version that has not shipped.

Before this repository

The first six versions came out of the project's previous repository. Their tags are not in this one and neither are their dates, so what follows is the shape of the line rather than a dated record — and nothing here links anywhere, because there is nothing to link to.

0.1.1 — the first Loment

A strict subset of Rust's syntax. That was the opening constraint rather than a style: the language was defined by what Rust had already settled, so there was very little to argue about and a compiler to build. It no longer claims to be a subset — the overlap is still there, the claim was dropped when the surface grew past it.

0.1.2 Alpha — the first self-hosting

The language begins to be written in itself. What that buys is not elegance: a compiler written in the language it compiles is the only way to find out what the language cannot express.

0.1.2 pre1 — repairs

The problems the first self-hosting turned up. A pre-release is where that kind of thing is supposed to happen.

0.1.2 pre2 — the base that still stands

The bootstrapping foundation every release since is built on: a compiler that rebuilds itself from a seed committed to the repository, and a check that the rebuilt seed equals the one it started from.

0.1.3 Alpha — the multi-syntax idea arrives

The first version where another language's source can be read as Loment. The meaning is always this language's; only the spelling is borrowed. It is the project's founding argument rather than a feature added on top, which is why it is listed here and not under "what else is different".

0.1.3.4 Alpha — the loop closes

All four stages — lexer, parser, checker and code generator — written in Loment, and the result reaches a three-stage fixed point. This is the last of the versions released from the previous repository, and the one every later version is measured against: it is the release the language and the compiler stopped needing a host to define them.

From this repository

The three versions that came out of this repository before the one shipping now. Each is a row rather than a section for the reason a record should give: the detail is on the release page it links to, and a history that keeps growing in full stops being a history and becomes a second copy of the archive.

0.1.4 Pre — the first installable Loment

2026-09-22. Put up as a pre-release for one reason: so that "the repository has versions" stops being a claim and becomes something you can look at. One detail survives it — the tag points at an earlier commit than the archives were built from, so GitHub's generated source archives are the tree before that build.

0.1.4 — usable

2026-09-23. The subject was being usable rather than having more in it: no syntax changed, and the work went into taking the last of the interpreter out of the path. Its Windows installer does nothing on machines that do not search the current directory; install from the zip if you want this version.

0.1.4.5 — reclamation, and a runtime that is a guarantee

2026-10-13. The four-rung reclamation ladder with an adaptive and a generational half; no_runtime became a guarantee rather than a declaration; networking on both targets; and the fifth setting, vm, arrived with its release gate closed. A patch the same day changed only the Windows installer.

0.1.4.6 — the gates come down

2026-10-17. Four things that had been built but kept out of a release became reachable from one: an interpreter tier beside the compiler, libc and LibL, and the vm setting. The rest is the largest defect sweep this project has had; most of the issue numbers in the repository come from it.

New

  1. LVM — the interpreter tier, T0 to T3. It reads the same intermediate form the linker does, so a program never gains a second source of truth. T0 was the fourth reader of that form; T1 records a feedback profile without changing a byte of output; T2 moves instruction decoding out of the execution loop, 6.1× T0 on the corpus with byte-identical output; the compact form is 375.9 KB → 107.0 KB for the same unit; T3 adds guarded specialisation and deoptimisation. choose vm is accepted by this release — 0.1.4.5 refused it in a release build, and that gate opened here. What that does not mean: the interpreter is the repository's tools/lvm.py family, which the package does not ship, and the setting does not change what the compiler emits. The line is a declaration, not a guarantee — the same standing no_runtime had in 0.1.4.5.
  2. libc and LibL. A release build links a real libc.so.6 and runs it end to end. The LibL face — fopen/fread/ fwrite/fseek, the remaining printf formats, malloc/calloc as spellings over the builtin heap — is judged against the system's real glibc. The 0.1.4.5 lock on use libl and on libc is open.
  3. Threads. thread_spawn in the language, plus an os/thread library whose system-call numbers are read from the header rather than remembered.
  4. Four libraries, each judged against a real implementation. os — five modules against CPython in the same Linux environment; internet — seven modules against real resolvers and servers.
  5. LMS level 1 — a second memory architecture beside the collector: its checker (E028/E029) and its level-3 entry, in both implementations.
  6. A gate that can see the runtime, and distribution. The 104 criteria that need a produced binary now run natively on the Linux runner instead of skipping, and a criterion that did not run no longer counts as a pass. Read-only mirrors on four hosts; a Simplified Chinese README; the VS Code extension on the Marketplace.

Fixed

  1. Reclamation. The sweeper no longer clears four mark bytes per freed block, which had been collecting live blocks next to garbage; free checks ownership and refuses a double free; block-interior precision is per-site slot masks; an argument to a whitelisted system call counts as a borrow; a collection no longer empties the free list; the collection trigger is attached where the bytes are asked for and counts what the allocator consumes; a recycled block keeps its recorded size; a promoted buffer's words reach the root scan; and L2's epoch stops at the next same-name let, so two sibling loops no longer block each other.
  2. Diagnostics that used to be silent or wrong. @ at statement start, binary literals and the fall-off-the-end rule are rejected the way the reference rejects them; an unknown type is E030 rather than E002; seven cases that were silent, wrong or fatal now say what the reference says; the same program computes the same numbers in every surface grammar; use std no longer crashes; the formatter keeps comments and keeps declaration modifiers on the declaration's line.
  3. The emitter refuses what it cannot express. Mixed-width arithmetic, bool != bool in the self-hosted compiler, 11+ parameters, a struct whose last field has no trailing comma, and integer literals that do not fit their declared type are errors rather than invalid IR.
  4. Runtime and CLI. Array indexing and arithmetic are checked; division by zero is a trap with a message; the default tier's refusal names the right setting; let x = 1;, let a: f64, a bare return;, the compiler's own heap for brk, the 250-term expression and 400 nested blocks are diagnosed instead of crashing; Windows builds a PE rather than an ELF; loment check no longer exits 0 for a file that cannot be built.
  5. Linker. A negative index is sign-extended; the mirror linker reads 64-bit globals and multi-line case tables.

New issues

One defect that this version's own additions introduced, and that is open: #442. Defects that predate this version are in the repository's issue list, not here.
