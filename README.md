# loment-site

Loment 的官网。静态站，手写 HTML/CSS，没有构建步骤、没有依赖。

站点出**五种语言**：英文（根目录）、简体中文 `/zh/`、日本語 `/ja/`、Русский `/ru/`、
Español `/es/`。**英文是唯一的源**，其余四种是它的译文 —— 所以对外材料的正本仍然只有
一份，译文不会变成第二个事实来源。这份 README 是给维护者的，所以是中文。

## 顶栏导航（2026-10-11 收成六项，2026-10-13 加到七项）

```
Learn · Get started · Examples · Standard · Versions ▾ · Systems ▾ · GitHub
```

**为什么收**：页面涨到十页时平铺是九项，桌面宽度只剩 166px 余量，窄屏要折三行。
把四个系统归到一个组、两个版本页归到一个组，顶层回到六项，桌面余量 317px。
2026-10-13 为《Loment 语言标准》加回第七项 `Standard`（放在 Examples 之后）——
余量仍够，俄文那行最长，实测顶栏仍是一行。

- 两个组是原生 `<details class="navmenu">` —— **没有 JavaScript**。
- **整条顶栏一次只开一个**：两组和语言切换器都带 `name="bar"`，浏览器原生手风琴
  替我们做互斥（否则两个面板会互相遮挡，实测过）。旧浏览器不认 `<details name>`
  时退化成"都能开着"，不是坏掉。**`name` 由 `tools/i18n_check.py` 的
  `canonical_lang_block` 写在切换器上**，改那一处要顺带改导航。
- 窄屏（≤860）菜单锚在**右**边（`.navmenu ul { right: 0 }`）—— 那时导航在自己一行上
  且靠右，往左挂会跑出窗口。
- **导航是手写的、各语言文字不同，工具不管它。** 加一项要改 5 × 页数 个文件；
  做法是写个脚本按语言把整个 `<nav>…</nav>` 重写一遍（先例见提交历史里那次"重写导航"），
  别一个个改。

## 多语言

**英文页是源，译文页是派生物。** 派生的问题是"源改了、派生物没跟上，而且没人发现"，
所以这里有一个工具专门看这件事 —— 与仓库里 `docs/i18n/glossary.md` §2 的翻译戳、
以及发布清单、自举种子，是同一套办法。

```bash
python tools/i18n_check.py          # 校验
python tools/i18n_check.py --fix    # 把英文的代码块搬进译文、重建 alternate 组与切换器
python tools/i18n_check.py --stamp  # 重盖翻译戳
```

它钉住这些：

| | |
|---|---|
| 齐全 | 五种语言 × 六个页面，没有多余页面 |
| 路径 | `<html lang>` 与目录对得上 |
| `hreflang` | 每页六条 `<link rel="alternate">`（含 `x-default`）**逐字节**正确 |
| 切换器 | 顶栏那个 `<details class="lang">` 逐字节正确，当前语言带 `aria-current` |
| 代码区 | 每块 `<div class="codewrap">…</div>` 与英文**逐字节相同** |
| 结构 | `<section>` 的 class 序列一致 |
| 链接 | 本地链接目标集合一致 —— 译文不得引入新链接，也不得丢掉链接 |
| 翻译戳 | 译文页头的 `source-sha256` 等于英文页"散文面"的 sha256 |

**代码块与命令输出不翻译。** 这是仓库里 `docs/i18n/glossary.md` §3 的既成规矩，
在这里由判据强制：译文里那块代码与英文**逐字节**相同。要改代码，改英文页，
然后 `--fix` 会把新字节搬进四种译文。`<p class="out">` 里的命令输出同理。

**翻译戳过期 = 英文改了、译文没跟上。** 散文面 = 除代码区与语言切换器之外的全部可见
文字（空白归一后按序拼接）。所以改一句英文，四张译文页的戳一起红 —— 那正是要看见的信号，
不是噪音。把译文改到跟上，再 `--stamp`。

**站址只写在一个地方** —— `tools/i18n_check.py` 顶部的 `ORIGIN`。换域名时改那一行，
跑 `--fix`，30 个页面的 `hreflang` 会一起重写，跑不出"漏掉某一页"这种形状。

**加一个页面要动的地方**（今天**工具只管 head 段、顶栏切换器与代码块，不管导航**）：

1. `tools/i18n_check.py` 的 `PAGES` 加一条；
2. 五种语言各写一份；
3. **顶栏导航要在 30 个页面里各加一行** —— 导航是手写的，而且各语言的"入门/示例"
   那两项文字不同，所以不能靠工具统一生成。链法是页内相对（`zh/` 里也写 `libl.html`，
   不是 `../libl.html`）；**只有仓根资源**（`style.css`、`mark.svg`）才带 `../`。
   插错位置这件事发生过一次：正则先撞上导航里那条 `lompi` 链接，于是新项落到了
   第一个 `</a>` 后面、跑到别的条目中间去了 —— 判据因此从"比链接集合"改成
   **按文档顺序逐条比**，这类挪位子现在会红。
4. 首页 `Systems` 那一节如果有新条目，**别把条数写进标题**（原来叫 "Three systems"，
   加了第四个就过期了 —— 这正是硬约定第 1 条要防的）。

**字体不带 CJK。** `Bitter` / `Public Sans` / `JetBrains Mono` 只有拉丁字形，
三种栈的末尾都接了系统 CJK 字体（`style.css` 的 `:root`）。这是故意的：CJK webfont
动辄几兆，而读者机器上那几套（苹方 / 微软雅黑 / ヒラギノ / 思源）比一个没人调过的
子集更好。日文另有一层覆盖，免得落到中文字面（macOS 自带 Songti SC，不挡的话
日文页的汉字会用中文字形）。

## `roadmap.html` 与 wiki 的分工（**别让它长成第二份路线图**）

路线图在**两个地方**：官网上这一页，和 wiki 的 `Versions and roadmap`。两处英文 = 漂移风险，
所以分工写死：**官网上这一页只放"形状"** —— 哪一版为了什么、什么已经落地、什么没有；
**细节、逐条状态与版本日志留在 wiki**，页面结尾链过去。往这一页加内容前先问一句
"这该在 wiki 上吗"。

页上必须留的三句：**没有日期**、**没有一样现在能下载**、以及**这个项目不把计划放在公开的
issue 追踪器里**（记成仓里带编号的设计文档，**那些文档是中文的** —— 不知道这件事的人会去
错误的地方找路线图）。

**写路线图之前先核 `origin/main` 的 `docs/210`。** 2026-10-11 踩过一次：wiki 与官网两边都
写着"分代没做、写屏障无处可放"，而 `docs/210` §2.7 记着分代那天早就落地了，当初挡着它的
那条理由（指针只存局部/形参槽）**已经作废** —— 于是官网的 LGC 页与 LVM 页**互相矛盾**。
撤掉一句过期的话时**要写明"这条理由作废了"**，别悄悄删：这个项目连自己撤回过什么都记
（`--stamp` 的规矩也是同一个道理）。

## 发布说明的写法（`releases.html` 的最新一版）

形状是用户 2026-10-12 定的，照抄即可：

```
0.1.4.5
  <h3>New</h3>   <ol class="notes"> 编号列表
  <h3>Fixed</h3> <ol class="notes"> 编号列表
  <h3>Not in this release</h3>  <p class="limit">
```

- **`<ol class="notes">` 里的编号由 CSS 计数器画**（`ol.notes > li::before`），HTML 里
  **不写数字**。手写 `1.` 会变成两组编号叠在一起。
- **内容从 PR 归纳，不从提交归纳**：`v0.1.4..origin/main` 是 573 个提交、173 个合并，
  只有按 PR 才看得出条目。取 PR 用
  `gh pr list --state merged --json number,title,mergedAt --jq '[.[]|select(.mergedAt > "<发布日>")]'`。
- **新旧两侧都要有"但是"**：`New` 每条都带它的代价或边界（`--opt` 省了自带链接器的
  理由、网络没有库也没有闸门、`vm` 只有维度和闸没有引擎），`Fixed` 每条都只说事实。
- **每一版都要写"不在里面"** —— 0.1.4.5 那一版是 libc 与 LibL。
- **`Fixed` 要按 issue 逐条写，不只写 PR。** 用户 2026-10-12 的裁决：0.1.4.5 合入了海量
  issue，**每一条缩成一句、带 issue 链接**列进 `Fixed`。取法是
  `gh issue list --state all --json number,title,closedAt`，筛 `closedAt > <上一版发布日>`。
  0.1.4.5 那一版是 **29 条**，几乎都是表层语法扫面查出来的（`choose write grammar c` 一族）——
  引导句说明它们的来历，点明"每一条都是前端可能把你写的东西弄丢的一种方式"。
  **wiki 上那份要同步**（同一份内容，`#` 编号列表）。

## ⚠ PR 一合，官网的状态句就过期

这是这一类页面**最容易烂**的地方，而且比版本号难发现 —— 因为它读起来完全正常。
2026-10-12 实测：`lvm.html` 与 `libl.html` 都写着"不在 main 上、还是个开着的 PR"，
而 **PR #249 / #245 当天已经合了**。那两句当时是**真的**，过期之后仍然通顺。

**规矩**：写或改任何一句"'X' 不在 main / 还没合 / 还是个 PR"之前，
**先 `git fetch` 再看 `origin/main`**；核完把"在哪一侧"写成**具体的那一侧**
（"在 main 上、不在任何发布里"），别写"还没好"这种会自己变味的说法。
`releases.html` 的每一版也一样：**发布说明写完要回头核一遍**，那几页最容易被发布这件事本身越过。

## 对外文字怎么说话（2026-10-12 全站改写）

用户 2026-10-12 的判断：**「现在的网页不像是给人读的，晦涩难懂」**。量过才动的手，结论是
**不是句子太长** —— 首页平均 17.5 词、`start.html` 15.6 词，都是正常散文的长度。是这四件
事一起造成的：

- **首页前 250 词里有 9 个读者不可能知道的词**（`sealed` `hosted` `artifact` `runtime`
  `libc` `root unit` `form object` `unit` `IR`），一个都没解释；
- **这一站是靠"减去什么"来介绍 Loment 的**，而减法的基线读者还没有 —— 读者学到的第一件事
  是"没有 runtime""没有 `printf`"；
- **段落的主语是那场设计辩论**，不是读者的程序（"Most build settings live outside the
  language, where a reader of the source never sees them…"）；
- **`learn.html` 有 14% 的段落是 caveat，导语就是其中一条** —— 读起来像在跟一个假想的
  批评者答辩。

参照系是 **rust 官网的结构**（**不是它的文案、不是它的版式**，见上一节那条禁令）：它的
首句主语是**语言**、宾语是**人和软件**；全页只出现两个内部术语；"没有 GC"放在
**Performance** 底下第三段，是性能的解释而不是身份声明；章节标题写的是**读者想要的东西**。
**它首页一条局限都不写 —— 这一条不学**，诚实正是本项目最好的东西。

### 六条改法

1. **标题写读者拿到什么**，不写设计在回答什么问题。
   （`Who can run what, in what scope` → `What a program is allowed to touch`）
2. **术语第一次出现就地解释**，括号里，五个字以内，或者干脆换个说法。
   （`sealed`（链不进任何东西）/ `hosted`（可以用系统库）/ 形式对象（产物携带的可读摘要））
3. **先结果，后机制。** 先说读者的处境或他拿到了什么，再说为什么这么设计。
4. **"没有什么"必须跟在"这给了你什么"后面**，不许单独成句。
5. **`.limit` 一条不删**，但一律移到"讲清楚之后"。"诚实保留，位置改"。
6. **首页加一节"它已经在用来做什么"** —— 不按领域许愿（没有生态，许愿就是撒谎），
   只列仓里真做出来的东西：工具链自己、`ahci.lomt`、`lumtui`。

**改一句英文 = 四张译文的戳立刻过期。** 所以**整页要说的话先想好再落笔**，别边改边想 ——
边改边想会把四张译文来回折腾四遍。

### 首页是自述，不是说明书（2026-10-14，用户裁）

用户原话：「重做 Loment 官网首页……一句话：Loment，因 AI 而诞生，服务于所有使用它的人……
整个首页就简短几句话没有什么技术发布，只是简短的诉说 Loment 的初衷……
**不需要在下面引用任何子页面或跳转**」。

所以 `index.html` 的 `<main>` **只有一个 `<section class="hero">`**：eyebrow、`h1`、
一段 lede、两个按钮（下载 Loment / 了解更多）。**没有代码块、没有 `.limit`、
没有 doclink** —— 顶栏是这一页通向外面的唯一路径。

⚠ **这是全站唯一"没有 `.limit`"的页面**，与 `releases.html` 属于同一类**具名例外**：
`releases.html` 的例外是"题材就是版本"，这里的例外是"**它不做任何技术主张**"。
`.limit` 的活儿是标出**主张**的边界（`docs/158` 那条诚实边界纪律），
而这一页只陈述意图 —— 没有可越过的边界，硬加一条反而把自述变成技术页。
**下一个人看到首页没有 `.limit` 时，要知道这是裁决过的，不是漏了。**

配套的一处样式：`.hero` 加了 `min-height: 70vh` + 纵向居中。没有它，这么短的正文会让
页脚飘在屏幕中间，看着像没做完。**用 70vh 而不是 100vh**：顶栏在宽窗口是 64px、
窄屏折行后到 ~110px，按视口精确算会在手机上多出正好那么多。`.hero` 只有首页在用，
所以这条改动不外溢。

### 术语的两个登记口

除了首页与系统页，其余页面说 **binary**（不再说 `artifact`）、**setting**（不再说
`dimension`）—— 这两个词读者能懂，而原来的两个得先学过这行才知道。**例外是
`releases.html`**：发布说明是记录，用的是项目自己的词（`artifact` / `dimension`），
而且与 wiki 上那份逐字同源。**要动它就连 wiki 一起动**，别只改一边。

### ⚠ 派完 agent 就别再回头改英文（2026-10-12 踩过）

这一轮四个译文 agent 已经跑起来之后，我又回头把 `lgc.html` 和 `lvm.html` 的两句话改了
（`dimension`→`setting`，`artifact`→`binary`）。结果 zh / ja / es 三份译文在那两处留了旧词
（ru 碰巧因为把 setting 也译成 `Измерение` 而没踩到），**事后靠人工逐条比才找回来**。

**判据查不出这件事。** 它比的是结构、链接、代码块和**整页散文面的哈希** —— 一份 99% 跟上了
的译文，戳照样是绿的。所以凡是要动英文，**一次动完再派 agent**；派完再动，四份译文里就会
有几处悄悄落后，而没有任何东西会告诉你。

## 视觉方向（2026-10-11 改版）

**取的是 rust 官网那种美学方向，不是它的版式。** 具体差别：字体是
`Bitter`（板衬线标题）/ `Public Sans`（正文）/ `JetBrains Mono`（代码），
**不是**它的 Alfa Slab One + Fira Sans；配色是自己的（墨蓝字 + 白纸 + 一个蓝强调色），
没有搬它的琥珀/靛蓝/绯红。**不要为了"更像"去换字体或抄它的细节** —— 那既侵权，
也让它看起来像山寨。

**入场动画（2026-10-12 加）**：打开一页时顶栏淡入，下面各块上浮 8px 落位 ——
**只用 `opacity` 与 `translateY`**，留在合成层，不触发布局。四条规矩：

- **`backwards`，绝不用 `both`。** `both` 会让元素在动画起来之前一直停在 `from` 那一帧
  （`opacity: 0`）—— 浏览器不跑这个动画、或样式表比内容后到，页面就**整片看不见**。
  `backwards` 只在**它自己那段延迟**里隐藏，元素的常态就是可见态。
- **顶栏只做透明度**（`settle-fade`）：它是 `position: sticky`，给它加 transform 会在动画
  期间把它变成包含块。
- **`prefers-reduced-motion` 那条必须同时把 `animation-delay` 归零。** 只归零
  `animation-duration` 会留下 0.2s 的"延迟 + 0.01ms"，那就是 **0.2s 的隐形文字**。
- **不要按段落错峰。** 读者真正看见落位的只有顶栏、抬头、以及至多第一段 ——
  其余都在首屏之下，看的时候早跑完了。错峰只会变成一处会坏的编号
  （`main` 的第一个 `<section>` 是 `.hero`/`.head`，不是 `.sec`）。

母题取自 Loment 自己的概念 —— **边界**：封闭的用**实线**框，对外的用**虚线**框
（首页那对 sealed / hosted 面板，即 `.split` 那块）。**全站只有这一处允许虚线**，
所以它读得出来。加新组件时别用虚线。

`.limit` 那个赭石色左规的组件是"诚实边界"的标记，与 wiki 上 `Template:Not shipped`
是同一个装置 —— 全项目一套，别另发明一个。

## 硬约定

**1. 不放会过期的事实。** 这是这个站最容易烂掉的地方 —— 它上一版
（`fujojtop.github.io/FujoOSwebsite/loment/`）在 0.1.4 发布后仍在说"预编译工具链尚未发布"，
还挂着一个"立刻使用"的弹窗。

所以：

- 所有下载链接写 `releases/latest`，**不写版本号**，也不写归档文件名
  （文件名带版本号）；
- **不写**模块数、示例数、内置命令数、语言数这类会随仓库变的计数；
- 版本号只在必须的地方出现，且以仓库为权威。**唯一的例外是 `releases.html`** ——
  那一页的题材**就是**版本，所以页面上写明它是例外，并且**下载按钮仍然指 `releases/latest`**。
  加这一页时最容易做错的一步是"顺手把版本号改成链接或删掉"：那一页这样写是有意的。

**2. 代码示例必须真跑过。** 不要凭语法印象写。跑法：

```bash
# 用发布版（用户实际会拿到的那个）
#   https://github.com/Loment-Lang/loment/releases/latest → linux-x64.tar.gz
loment run examples/hello.lomt
```

`examples/*.lomt` 是站上代码的源。改了 `examples.html` 里的代码就要同步改源文件并重跑 ——
两处不一致的话，源文件就是错的，因为它声称自己对应站上那段。

**3. 已知跑不了的东西，要么不放，要么如实标注。** `examples.html` 末尾那段注记是范例：
capability 不在那四个示例里，因为它在本版**链接不过去**（自举链接器的缺陷，参考实现没事）。
站上不假装它能跑。

**4. 改英文页 = 同时欠四笔译文。** 见上面「多语言」。散文面一动，四张译文页的翻译戳
立刻过期，判据会红 —— 别去把 `--stamp` 当成消红的手段重盖一遍：那正是它要拦住的作弊。
要么把译文改到跟上，要么承认那四页暂时落后（红着）。

## 改与发

改完直接 push 到 `main`，GitHub Pages 从分支直接服务（`build_type: legacy`），
没有 CI、没有生成步骤。push 之前跑一遍：

```bash
python tools/i18n_check.py
```

本地预览：

```bash
python -m http.server 8000
```
