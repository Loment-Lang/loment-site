Tur 2026.3, test build two: borrow lifetimes and a store that fills the gaps

The second complete test build of Tur 2026.3 is ready. Borrow lifetimes are now in both implementations, lgc gives the collector a clock, and the store has grown to 332 modules so a program can ask for the conveniences Loment leaves out. The edition is still under development.

This is a test build, not a release, and Tur 2026.3 is not finished. The stable channel stays on 0.1.5.1; the Playground's Beta channel follows main. Anything described as coming next is a direction, not a date.

What a test build claims

A test build is the whole edition put together and exercised at once: both compiler implementations, both artifact paths, and the full store. The first build carried the domain and LSPE work; lifetimes were the next line. This second build is the first time borrow lifetimes and the expanded store are in the same tree. It is a checkpoint, not a tag.

The claim is narrow and testable: the reference compiler in tools/lomentc.py and the self-hosted compiler in loment/selfhost read the same Tur 2026.3 surface and emit the same IR for the corpus. When they disagree, the build is not done.

Borrow lifetimes, without a lifetime syntax

&T and &mut T are now first-class types: parameters, returns, struct fields and generic arguments. The dimension is choose lifetime_no | lifetime_auto | lifetime_manual. lifetime_auto is the default from tur2026.3 on; older editions keep lifetime_no, so their artifacts do not change by a byte.

The surface stays quiet. One borrow input means every borrow output borrows from it; several borrow inputs and one output means the shortest of them, so fn min(a: &[u32], b: &[u32]) -> &[u32] needs no annotation. Methods borrow from self. Only a return that must pick one specific input writes that parameter's name, as in -> &a [u32]. A borrow is a ptr in the artifact; slice borrows normalise to the existing views; *r dereferences and r.field auto-dereferences.

The self-hosted side caught up on 2026-11-08: it no longer rejects borrow types by name. E041 now appears only when a region does not hold — a returned borrow with no borrow parameter, a marker on a parameter that does not exist, or free(p) while p is borrowed. A stored &mut excludes later borrows as E007. These are the same five rules on both sides.

The honest boundary. Borrows as generic arguments are reference-side only; the self-hosted registration is name-level, so only let x = &mut y enters its exclusive table. The design is docs/299.

lgc gives the collector a clock

Tur 2026.3's other feature is lgc: manual timing for the collector. lgc start(10ms) { … } opens a collection window with a cooperative time budget; lgc start { … } opens one without a budget; lgc end; pauses and lgc start; resumes. lgc end { … } is a scoped pause that restores the previous state on exit.

It works in every choose gc mode, and no_gc plus lgc is E039 because there is no collector to control. The budget gates starting a collection; it does not preempt one already running. It is not a fourth GC tier — choose gc remains the tier choice.

The store reaches 332 modules

Loment is small on purpose. The store is where the conveniences live: ordinary Loment source, compiled by both implementations, with every public name listed in docs/store-index.md. It now holds 13 packages, 332 modules and 2791 public functions. std is 148 of them; the rest are os (44), system (41), world (22), dev (15), lowlevel (12), internet (11), math (9), host (8), science (6), baremetal (6), windows (6) and engineering (4).

The latest batch closes five structural gaps. Cryptography and networking gained ChaCha20, Poly1305, AEAD, AES-CTR/GCM, x25519 and ed25519, plus AF_UNIX with SCM_RIGHTS and a TLS 1.3 client core. The composition layer gained an event loop, atomic file operations, a bounded channel, a job queue and a small HTTP server. A windows package names the Kernel32 surface. Shared modules replaced duplicate code inside os and system. A generated index and a task-oriented cookbook make the store searchable without reading every file.

What the store does not hide. The TLS module is a client core, not a claim of interoperability with real servers. The windows modules are a declaration surface until PE FFI lands (#1262). Loment has no function pointers, so the event loop dispatches by tag and the HTTP server returns handler ids. thread_spawn needs a compile-time function name, so the job queue gives you a queue and you write the worker.

What is still missing

Tur 2026.3 is not closed. lifetime_manual accepts the &a T marker, but the wider annotation surface is not there. Extension domains, the solid body of the graph model, the → / ≺ / × domain forms and the wasm32 backend remain design or later work. The store's platform and protocol edges are written down as boundaries rather than filled in.

The second test build is the point where the edition can be tried as a whole. It is not the point where it is finished.
