ROAD TO FUTURE // PLAN 2026 →

Blog · 2026-11-17

Road To Future

I think it is time to announce an ambitious plan: Road To Future. The name is plain on purpose. What sits behind it is a queue of work that will take more than one release.

This is a direction, not a release. I have an order; I do not have a calendar.

Why now

2026 carried the project across a line. The reference compiler and the self-host compiler agree on the core, domains and borrow lifetimes exist, LSPE has its four parts, LVM has tiers, and ELF, PE and the Playground all run. The base is good enough to build on. The question is how much language can stand on it.

I keep running into the same list. Classes are not finished. Effects have declarations and no runtime. Graph types still behave like an encoding inside a library. Part of the domain story stops at the compiler's front door. Some LMS levels are budgets and declarations. These are not small gaps; they are the shape of the next year.

Road To Future is that list turned into a queue. It says what comes first and why. It does not put a date on the end.

Seven strands

1. LSPE, organized and faster

LSPE works. Adding a checker still means knowing too much about the compiler's insides. I want the registry, the scheduler and the ledger to be the normal way to add a check, with a small SDK at two levels: advisory checks, and checks that can stop an artifact. Classes belong here too: the framework should be written with the inheritance it is meant to audit.

2. The features the language is missing

Classes are first. Single inheritance, fields, non-virtual methods, self and construction are in review now; virtual dispatch, vtables and super come next. Function values and indirect calls landed earlier this month. After that I want pattern matching and destructuring, a clearer module and visibility story, and the unglamorous pieces: collections, error handling, and diagnostics that name the value the user wrote.

3. Capability domains, researched and completed

All eighteen domain kinds ship. The next work is semantic. A space tag should survive a call. An automatic guard should cover more than direct indexing. Block domains should appear in Potato. subject and witnessed need a real provenance story. Some of this is compiler work, some is language design, and some may end with a documented limit.

4. Graph types as first-class values

DGT is the second core of 0.1.5.2. digraph<K> is a compile-time graph value with a capability lattice, layout specialization and static verification. I want graph types to be first-class: a graph you can name, pass, query, traverse, serialize and verify before the program runs, instead of a library encoding the checker cannot see.

5. More substance in Tur

Tur has a frozen reading, a closed reading and a moving one. New surface syntax enters only when both implementations, the checker and the artifact agree. Candidates include effect syntax, graph literals, class syntax and pattern matching. Every addition keeps the default artifacts byte-identical; a choose dimension or an edition boundary is how that stays honest.

6. LMS, optimized and modernized

LMS has seven levels and a lot of good intentions. Some levels are still budgets and declarations. I want enforcement where the level promises it, costs a reader can see, and clearer escape hatches. It has to meet lifetimes and LGC in one object model, or the same pointer will get three different stories from three checkers.

7. Algebraic effects: checker and manager

A2 parses effect declarations and rows. perform, handle and resume stop at E023. The next stage is a real runtime: handlers, continuations, scheduling, cancellation and budgets, plus a checker for row subtyping and exhaustiveness. This is the most research-shaped item on the list. I am not going to call it a weekend patch.

And the rest. Self-host parity, the package store, the Playground, documentation and performance. These are a standing line, not a phase.

The order

Classes first, because the LSPE framework will be written in them. Domains and graph types next, because they share the static-verification story. Effects after that, because they touch capabilities, lifetimes and GC at once. Tur surface follows each substrate. LMS moves alongside; it is too cross-cutting to leave for the end.

Each step follows the same gate: a design note in docs, tests that are red before the change and green after, generated artifacts in their own commit, and no movement in the default artifact. If a piece cannot meet that, it waits or gets an explicit exemption.

What stays true

The two _off values stay byte-identical. L0 is a frozen contract; adding or removing a primitive is a versioned change with downstream notice. There is still no open world, no reflection and no runtime type names. The self-host compiler stays in the loop, or the change does not land.

Where to follow

docs/345 has the class ladder, docs/344 has the LSPE framework, and the roadmap has the release order. I will keep opening issues with the smallest program that shows a gap. If you hit a wall, that small program is the most useful thing to send.

The road is long; the first marker is already in review. — Loment Dev Fujo
