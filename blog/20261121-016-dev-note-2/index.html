Blog · 2026-11-21

The time bridge

Memory safety deserves to be taken seriously. Everyone working on Loment has kept looking for ways to solve the hardest problem in systems programming, and the answer has arrived as a major update to LVM and LMS. This is the second 0.1.6 development note.

This note is about work in review. The three changes it describes are open, not merged; the stable release is still 0.1.5.1. The parts that are already on main are named as such.

Memory is the whole subject

A pointer outlives its object, an index passes a bound, a generation goes unchecked, and the program reads or writes something it does not own. The field has carried that problem for decades. Loment's answer has never been one mechanism: LMS checks at levels, capability domains scope authority, the borrow checker reasons about lifetimes, the GC ladder chooses reclamation, and LSPE audits the result. LVM is the engine all of it eventually runs on.

An outside proposal, PANGU Ω, arrived with a seven-layer architecture. We compared it against the tree: five layers already had counterparts, and three things were genuinely missing. Those three became documents, and the documents became the changes below.

LMS grows a fault ABI

The native g1 overflow check used to end in __loment_abort, which lowers to ud2 — SIGILL, exit 132, with nothing a tool can read. Under choose lms_pangu_true it now calls __loment_fault(1) and exits 101; the other two fault kinds take 102 and 103. Every fault names its site as fn:blk#idx, the same coordinate the LVM substrate reports. A census walks every guest load, store and atomic read-modify-write and writes that coordinate down. The self-hosted compiler emits the same fault text, the seed was regenerated, and the two implementations' fault sections are byte-identical.

One real bug fell out of the work: the IR cache key left user switches out of the source digest, so changing a choose line could hand back a stale artifact. That is fixed.

LVM becomes a machine

LVM-A is an abstract machine with six primitives: site, capability check, generation check, fault, checkpoint, resume. It can be implemented on four substrates: sw_cap, sw_tag, hw_cap and hw_tag. The first one landed: an object table with base, limit, generation, alive bit and kind; capability propagation through SSA values, GEP bases, parameters, stored pointers, phi nodes and inttoptr; and a capability check before every guest load and store. A failure exits 101, 102 or 103 and names the site. The default substrate is none, so ordinary programs emit what they did before.

The boundary is stated as clearly as the feature: a capability is lost after an address is laundered through as u64, and a dangling pointer after address reuse is not caught yet, because the object generation has to travel with the pointer.

Snapshots both interpreters can read

Checkpoints used to be an internal detail. They are now a format: both interpreters write the same LVMC bytes — 4 MiB of memory, 32768-byte frames, depth 32 — and resume each other's snapshots. Programs are carried by name, not by block number, because the two parsers number blocks differently. The command line is part of the snapshot, and a resume can be handed a different host argument vector.

A restore bug was found and fixed: a base was written as a byte offset and read as a word offset, so the first return after a resume retired the whole object table. The seal is a sidecar, not a compiler output: it carries the artifact hash, the per-site ledger, the substrate profile with its guarantees and assumptions, a zero-import verifier, and the same-artifact genesis attenuation. Schema 2 also carries each interpreter's byte and line price with a budget — 8000 lines and 320 KiB, measured at 7,936 lines today.

Faults become readable

When a program dies, the interesting part is usually not the signal. LVM faults now print a Lomenterr-shaped block after the stable first line: object table entry, offset and overrun, retired generation, site and advice; llvm.trap gets the same treatment. On the native tier a fault has stages. A ptrace reporter gives the signal, si_code, address, PC, RSP and an optional source line. lomelf --fault-report makes the artifact report itself from an alternate stack, with the read or write direction, address, PC and RSP, site and a stack-overflow hint. The self-hosted linker produces the same ELF byte for byte. A small optional step goes further: --fault-heal N zero-maps an unmapped page below 1 MiB and returns to the same instruction, on a budget. Page zero stays fatal by default.

Two bugs came out of building the mirror: fn main entries were emitted as call i32 @main without parentheses, a path that had never compiled, and a fault in a function prologue could be attributed to the previous function's last site. Sites now carry their lowered code length and the lookup is a half-open range.

The notary

An audit is only worth something if the auditor sits outside the thing it audits. LNotary is a separate artifact auditor that reads Potato and imports none of the toolchain — not the compiler, not the Potato module, not LSPE. It checks the self-consistency of the systems table, the GC ladder, the LMS levels and budgets, the LSPE ledger and the switches. It derives a lawspace sidecar with dimensions, laws and a content-addressed seal; verifies the site table and binds it into that seal; and verifies a same-artifact derivation chain where capabilities, budget and depth only shrink. It is active only on LVM-enabled artifacts and says so by name otherwise.

The time bridge

Here is the part worth the name. The six primitives are the same abstract machine on every substrate. A seal records which substrate the artifact was built for, together with its guarantees and assumptions. The one hard criterion is B5: the same IR sealed for sw_cap and sealed for hw_cap carries the same bytecode hash. That is what makes a hardware generation change a re-seal instead of a recompile.

Five of the six hardware primitives are missing or partial on current silicon. The LVM tier is how the language crosses that wall without waiting for the next generation: instruction-level marking disappears inside the machine, the two bounds checks become costs rather than walls, write authority becomes an instruction, exact checkpoints become feasible, and the unverifiable-ISA wall moves down one layer, where the axiom becomes “the CPU executes the interpreter correctly”. The trust chain has four links: bytecode and seal, the LVM-A model, the two interpreters, and the host ISA.

The update path

One more open change belongs to this story. Hot updates used to replace only the running language-server image; the linker, the compiler, the CLI and the build tools in bin/ never reached an installation. The new payload carries every tool, built from the projection tree on the release seed, packed and signed. The updater verifies a raw Ed25519 signature and every SHA-512 digest with the standard library, writes the inactive generation, and only then flips current. Check, rollback and status are supported. A stock 0.1.5.1 installation gets a one-time bootstrap, because it has no updater and no pinned key to start from.

What is not done

The three changes are open. sw_tag exists only in the reference interpreter. Cross-implementation resume is proved on twin fixtures, without real file I/O or a mid-phi resume. Capability precision is rebuilt by address on the self-hosted side. Native diagnostics are ELF-only and off by default; the Windows PE path is a later stage, and the report costs about 3.3 times the artifact size on a tiny program. Healing covers Linux SIGSEGV/SEGV_MAPERR below 1 MiB on a budget. Default builds emit what they always did.

At the start of 2027, you will be able to use this bridge.

The next note will say what merged. — Loment Dev Fujo
