A domain you can stand in, a complete LSPE, and lifetimes next

Three things are worth writing down this week: a domain stopped being a label at the top of a file and became a block you enter, all eighteen domain kinds now ship, LSPE has its four parts in the 0.1.5.2 beta, and the borrow-lifetime line is the next thing on the bench. This is the plain-language version.

This is a progress note, not a release. Beta means a snapshot of main; the stable channel is still 0.1.5.1. Anything described as coming next is a direction, not a date.

A domain is now a place in the code

The old shape was a declaration. You wrote capability blk_write : disk[0..4] once at the top of a file, then guard blk_write(slot) in a function. It told a reader what the code intended, and the compiler mostly took that line on trust. The new shape is a block. You enter it, the domain starts; you leave, it ends. Values say which space they live in, and indexing one of those values is guarded automatically.

A block written as domain buf : disk[0..63] consumed(1) { … }, with a value declared as a: [u32; 64] in disk, means that a[i] inside the block checks buf(i) before the access. An explicit guard buf(i) still works, and a guard after the block is a compile error because buf no longer exists.

The point is not prettier syntax. A domain now has a place and a lifetime. Stateful kinds allocate their state in the current frame, so every loop iteration and every recursive call gets a fresh instance instead of sharing one global table.

The honest boundary. A space tag does not travel through a call; the callee sees a plain type. Automatic guards cover direct indexing only, not ptr_add. Block domains are not in the Potato form object yet.

Eighteen kinds, three questions

Every domain answers three questions: where the index may be (shape), whether it marks allowed or forbidden territory (polarity), and when the answer changes (time law). The old ten kinds covered the common cases. The other eight landed this week, so all eighteen now ship, and both compilers emit byte-identical IR for every one.

In plain terms: an interval says where. consumed(1) says each position may be used once per instance. cyclic(P) wraps around. generational(N) flips its answer every N ticks. adaptive shrinks the allowed range from a quality byte. reachable(K) reserves a position for K ticks and expects a discharge. subject, witnessed and flow carry a second argument: a bitmask, a ticket, or a packed edge.

The boundary matters. subject and witnessed tokens come from the caller; the language counts uses but cannot make the token unforgeable — that needs linear values. flow is a packed range of edges, not an arbitrary edge set. Both compilers agree on the IR, and both say what they do not cover.

You can walk a domain

A domain used to be something you guarded. Now it is something you can traverse. domain:for i { … } walks the current domain's positions; domain:for i in buf step 2 names a domain and jumps; domain:for i, j in A, B walks two same-shaped domains in parallel; step -N walks backwards.

The loop is one guard at the head and a clock tick at every back edge. Units that use no domains do not change by a byte. choose domain_clock_explicit turns the automatic tick off if you want to drive the clock yourself.

Tree and graph edges became syntax too. child_of states a parent; couple A, B makes two domains renew as one unit, so a guard on either checks the other silently; mutex A, B is a compile-time promise that two finite, non-danger shapes never overlap. tools/loment_geometry.py prints the tree, the graph and the position axes as deterministic JSON.

What is still design: → delegation, ≺ ordering, × exclusion, extension domains, the tool domain, and the solid body of the graph. The pages and the compiler say so instead of pretending the map is complete.

LSPE is complete in the 0.1.5.2 beta

LSPE is the audit layer: it records what each judgement rests on. The 0.1.5.2 line had four parts, and all four are now in the beta compiler.

The questioner has eight engines (E1–E8): loops, well-formedness keyed by type and substitution, differential judgments that never discharge, and a probe registry generated from the test tree. The counter-asker has fixed question templates (Q001–Q013) and answer channels: the default is allow but label, defer and refuse are explicit, and strict mode makes an unanswered question an error. LSPC is the pre-flight sheet — twelve families by five columns, with full, quiet, strict and off modes; loment lspc check reads the front end without writing anything.

The ledger keeps the derivation tree, a proof hash per site, a .lspe sidecar, and invariants I1–I5. loment lspe why and loment lspe verify read it. It is in the Beta channel now. The Playground runs that snapshot, so Run, Check and Build exercise the same compiler; the Playground does not add an LSPE button, because the ledger is a command-line artifact rather than an action on a text box.

Lifetimes are next

The next line is borrow lifetimes. It is opt-in from the file header: choose lifetime_true. The goal is Rust's guarantees without Rust's annotation noise: no 'a, no <'a>, no where. &T and &mut T become first-class in fields, returns and generic arguments, and the compiler infers a region for every borrow and checks that it does not outlive its source.

Elision is deliberately aggressive. One borrow input means every borrow output borrows from it. Several borrow inputs and one output means the shortest of them — so fn min(a: &[u32], b: &[u32]) -> &[u32] needs no annotation. Methods borrow from self. Only when a return must borrow from one specific input do you write that parameter's name, as in -> &a [u32].

The checker follows LSPE's gentle philosophy: it names the source — which variable, which line — and explains the path, instead of printing “lifetime error” and leaving you there. Strictness is available; it is not the default. The lifetime domain series extends the same idea: a region is a place with an entry, an exit and a rule about what may cross it, and the checker asks the same kind of question LSPE asks.

This is work in progress, not a shipped feature. The umbrella is #1240 and the design is docs/299; the sub-issues are landing one at a time. Nothing here has a date.
