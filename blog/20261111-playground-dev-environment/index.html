The Playground is a small development environment now

I updated the Playground. It opens on a project manager, keeps a file tree, and can import a local folder. The reference compiler still runs in the tab; the page now has more of the shape of a place to work.

This is a Playground change. The language editions, the compiler and the channels are unchanged.

What changed

The first screen is a project manager. You can create a project, open a folder from your computer, or import a few text files. A folder keeps its relative paths, so src/main.lomt and docs/README.md arrive in the tree where they were.

Inside a project there is a file tree. Add files and folders, drag them between folders, pick the entry with the dot, and run either the entry or the selected file. The output header says which one is being compiled. Text files are read as UTF-8, UTF-16 or GB18030; binary and oversized files are skipped.

addin works when its chooseset unit is part of the project: Run now uses the same load_unit path as Check and Build, so the switch pre-scan sees the addin target.

Projects stay in this browser. Nothing is uploaded.

What it still is

It is still a browser tool. There is no terminal, debugger, Git, package install or long-running server. Editing, compiling and running happen in one tab; LVM still has a step cap, and browser storage has a size limit.

I kept the compiler surface fixed for this update. The next work can go back to lifetimes, GC timing and the rest of 0.1.5.3.

Try it

Open the Playground, choose Open folder for a project on disk, or New project to start from src/main.lomt.
