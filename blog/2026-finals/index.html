The Finals Of 2026

2026 is close enough to its endpoint to be looked at as a whole. This is the year-end note: what the year actually produced, what is still open, and what “finished” can mean when the calendar is the only deadline.

This is a status note, not a release. The stable channel is still 0.1.5.1; the Tur 2026.3 test build is not closed. Nothing here has a date.

The year in one page

2026 moved the project from 0.1.4 to 0.1.5.1. The surface grammar became a two-level edition system: Tur 2026.1 is frozen, Tur 2026.2 closed in November, and Tur 2026.3 is the open line. Domains became blocks with a place and a lifetime; LSPE gained its four parts; borrow lifetimes arrived without a lifetime annotation; the store grew to 332 modules; the Playground put the reference compiler in a browser tab; Java libraries became callable without a JVM; hot update became a release-shaped thing.

That list is not a feature count. It is the shape of the year: the language stopped being a set of promises and became a set of artifacts that can be checked, linked and shipped.

The last test build is still a test build

The second complete test build of Tur 2026.3 is out. It puts borrow lifetimes and the expanded store in the same tree, and both compiler implementations read the same surface. It is the closest thing the edition has to a finish line — and it is still a checkpoint, not a finish.

What is still open is not hidden: lifetime_manual accepts the &a T marker but the wider annotation surface is not there; extension domains and the solid body of the graph model remain design; the wasm32 backend is a design record, not a backend you can use.

What “finals” means here

A school year ends with finals because the calendar says so. A language does not. The edition is closed when the surface stops moving and the criteria are green, not when December arrives. So “the finals of 2026” is a place to stop and look, not a declaration that the work is over.

The honest year-end statement is narrower than a launch: the project can now be described in one page without inventing anything. That is the bar for the next year.

What is on the bench

The next lines are already written down: the wasm32 backend (docs/313), the next beta of 0.1.5.2, the graph and extension domains, and the store gaps that are still a branch rather than a release. None of them has a date.

The previous test-build note is here; the Playground is here. Everything else is in the repository.

A year is a useful unit for looking back and a bad unit for declaring a language finished. — Loment Dev Fujo
