Blog · 2026-11-18

0.1.6 development note #1

0.1.5.x is closed, and 0.1.6 has stopped being a line on a roadmap. This is the first note about what is moving inside it, written the way I would explain it to someone standing next to the bench.

A note records a moment, not a release. Some of this is in the reference compiler and not yet in the self-hosted one; some is a design with no code behind it. Each paragraph says which.

A function is a value now

You can put a function in a variable, pass it to another function, return it, and call it through the variable. A closure can capture the values around it, by value, or by reference if you name the reference. Calling through a value is spelled exactly like calling by name, so the code reads the same; only the compiler knows the difference.

This sits behind a new switch, choose fp, and it is off by default. With it off, the build is byte for byte what it was. With it on, the compiler can no longer see every call target, so it collects the functions whose address the program takes and refuses an indirect call that has no target of its own type. That check is the price of the feature, and it is stated plainly.

The compiler can take the type from the value

let x := e and let x: auto = e now mean the same thing: the local's type comes from the initializer. The first version keeps a tight rule — the initializer has to spell a type somewhere, in a variable, a parameter, a field chain, a whole cast, or true and false. A bare literal, a call or an operator is refused. A few built-ins return types that have no spelling in the source, and guessing them on one compiler while the other refused would turn a small convenience into a difference between two builds. The feature belongs to Tur 2026.3 and later; older editions keep their answers.

An error can be handled where it happens

catch used to give a fallback value and nothing else. Now it can also bind the error and run a small expression on it — catch |e| { … } — or turn the failure into an early return with catch return. The compiler already had the switch and the payload slot for both, so the cost is small and the error path stays visible in the code you wrote.

Classes: from a skeleton to real dispatch

A class lowers to a struct with the parent's fields in front, plus ordinary functions named after its methods. Single inheritance, fields, non-virtual methods, self and construction work in the reference compiler. Virtual methods followed: a virtual hierarchy carries a table at the front of the object, an override takes a fixed slot, super calls the parent directly, abstract methods are signatures with no body, and a reference to a child can be used where the parent is expected.

Two boundaries are worth saying out loud. Virtual classes need a runtime, because the tables are built with the allocator. The self-hosted compiler cannot read classes yet; this work is reference-side. The default build is unchanged.

Effects: the first slice that actually runs

Effect declarations have parsed for a while. Running them was the half that did not exist. A narrow slice now compiles: handlers whose arms finish by resuming once. The lowering is inlining — perform turns into a few bindings and the arm's body, and handle turns into its own body, so the rest of the compiler never meets a handler node. There is no continuation object and nothing is allocated on the heap, which is why the slice works under no_runtime with manual collection.

Everything outside that shape is refused by name: a handler that captures, aborts, or resumes more than once. Both compilers read the syntax; the runtime lowering is reference-side for now.

A third opinion on what a program means

Almost every test in the tree compares two implementations with each other. That is good at finding disagreement. It cannot find the case where both are wrong in the same way, and that has happened twice this year. The new piece is an interpreter written in Loment from the standard alone; it does not import the compiler, the linker or the formatter. It runs small programs and compares their results with expectations written by hand. It started with scalars, then learned loops, break, continue, strings and structs. It has already found a real difference between two editions — one accepts an assignment to a struct field that the other refuses. That is the kind of thing two implementations cannot tell you when they agree.

The audit framework stopped being a pile of checks

The compiler's checks now go through a registry, a deterministic schedule, two SDK tiers and a host that runs them. Fourteen built-ins sit in the plan, each with a phase, an id and a reason to be skipped. A check that only offers advice can ask a question. A check that claims evidence has to satisfy the obligation's acceptance set, and no obligation accepts outside evidence yet. Adding a check is now a matter of registering it, and the framework's public version stays at zero until that evidence surface stops moving.

Two designs on the bench

Two pieces are designs with no code behind them. The first joins borrows to domains. Three lifetimes already existed — where a value lives, whether its time window is still current, and who may write — and none of them talked to the others. The new rule set puts a borrow inside a time window, requires write authority on both sides, and allows one exclusive loan per law. The second is a compiler accelerator. A 5,000-line program takes about two seconds today, with the front end and the checker taking most of it; the target is one second. It would be a third implementation, and its IR, ELF and Potato output would have to match the reference byte for byte.

What is still open

The self-hosted compiler has function values and effect syntax, but not classes. The effect runtime is one narrow slice. The joint borrow checker and the accelerator are paper. That is normal for a first note. The rule has not changed: a feature is finished when both implementations agree and the gate can prove it, and the default build does not move until a switch asks for the new thing.

I will write the next note when there is another stretch worth describing. — Loment Dev Fujo
