リリース

リリース履歴

最初の Loment から、いま出荷されたものまで。各項目は、そのバージョンが何の ためだったか —— そしてその記録がどこにあるかを述べる。最も初期のものは 別のリポジトリからリリースされており、このリポジトリはそれらのタグを持っていないからである。

ダウンロード はじめに

これはこのサイトで唯一、バージョンを名指しするページである。他のどこでも ダウンロードリンクは releases/latest と言う。ページに書かれたバージョン番号は 賞味期限つきの事実だからである。ここではバージョンこそが主題なので、それらは 名指しされ、それぞれが実際に公開されたものを指し示す。そのいずれも、まだ出荷されて いないバージョンについての約束ではない。

このリポジトリより前

最初の六つのバージョンは、プロジェクトの以前のリポジトリから出た。それらのタグも日付も このリポジトリにはないので、以下に続くのは日付つきの記録ではなく、線の形である —— そしてここでは何もどこにもリンクしない。リンクする先が何もないからである。

0.1.1 —— 最初の Loment

Rust の構文の厳密な部分集合。それは様式ではなく、出発点の制約だった: 言語は Rust がすでに決着させたものによって定義され、だから議論すべきことはごくわずかで、 作るべきコンパイラがあった。もはや部分集合であるとは主張していない —— 重なりは いまもあるが、表層がそれを越えて育ったときにその主張は取り下げられた。

0.1.2 Alpha —— 最初のセルフホスト

言語がそれ自身で書かれ始める。それで得られるものは優雅さではない: 自分がコンパイルする 言語で書かれたコンパイラだけが、その言語が表現できないものを見つけ出す唯一の方法である。

0.1.2 pre1 —— 修復

最初のセルフホストが明らかにした問題。その種のことはプレリリースで起きるものとされている。

0.1.2 pre2 —— いまも立ち続ける基盤

それ以降のあらゆるリリースがその上に建てられているブートストラップの基盤: リポジトリに コミットされた種から自分自身を再構築するコンパイラ、そして再構築された種が始めたときの ものと等しいことの検査。

0.1.3 Alpha —— マルチシンタックスの発想が到来する

別の言語のソースを Loment として読める最初のバージョン。意味はつねにこの言語のものであり、 借りているのは綴りだけである。それは後から足された機能ではなく、プロジェクトの創設の論で あり、だから「ほかに何が違うか」の下ではなくここに挙げられている。

0.1.3.4 Alpha —— 一巡が閉じる

四つの段階 —— 字句解析器、構文解析器、検査器、コード生成器 —— がすべて Loment で 書かれ、その結果は三段階の不動点に到達する。これは以前のリポジトリからリリースされた 最後のバージョンであり、それ以降のあらゆるバージョンが測られる基準である: 言語とコンパイラが、自分たちを定義するのにホストを必要としなくなった リリースである。

このリポジトリから

いま出荷されているものより前に、このリポジトリから出たバージョンたち。それぞれが節ではなく 一行になっているのは、記録が果たすべき理由からである —— 細部はリンク先のリリースページにあり、 完全なまま育ち続ける履歴はもはや履歴ではなく、アーカイブの二つ目の写しになる。

0.1.4 Pre —— 最初のインストールできる Loment

2026-09-22。プレリリースとして置かれた理由は一つだけである —— 「このリポジトリにはバージョンがある」という主張を、主張ではなく、目で見られる事実に するため。作られ方について一つだけ残っていることがある: タグはアーカイブが構築された commit より前の commit を指しており、GitHub が生成するソースアーカイブはそのビルドの 前の木になる。

0.1.4 —— 使える

2026-09-23。主題は中身を増やすことではなく使えることだった: 構文面はまったく変わらず、作業はインタプリタの最後の部分を経路から外すことに注がれた。 このバージョンの Windows インストーラは、カレントディレクトリを検索しない設定の機械では 何もしない。このバージョンが欲しい場合は zip からインストールすること。

0.1.4.5 —— 回収、そして保証になったランタイム

2026-10-13。四段の回収のはしご。適応型の半分と世代別の半分を伴う。 no_runtime は宣言から保証になった。両方のターゲットでネットワークが動く。 五つ目の次元 vm が、リリースゲートを閉じたまま到来した。同日のパッチは Windows インストーラだけを変えた。

0.1.4.6 —— ゲートが下りる

2026-10-17。作られながらリリースから締め出されていた四つが、一度に 手の届くところへ来た：コンパイラの隣のインタプリタ段、libc と LibL、そして vm の次元。残りは 0.1.4.7 以前で最大の欠陥掃討である。

0.1.4.7 —— ライブラリが双子になる

2026-10-18。欠陥のリリースであり、見出しは機能ではない：パッケージが 同梱するすべてのライブラリが、二つの実装でバイト単位に同じ IR を生む —— 155 モジュール、 飛ばしたものはない。ここへ来るまでに掘り出されたのは、外から見えていた「分岐」ではなく、 静かな状態のバグだった。

0.1.5 —— 行列、そして最後のゲートが開く

2026-10-20。このリリースは、約束を、目で確かめられる成果物に変えることについて である。choose は七次元の行列になり、その合法なすべてのセルが 両方の実装でコンパイルされ、バイト単位で比べられる。安全メモリマネージャと監査台帳が出荷され、 インタプリタはツールチェインとともに出荷され、そして最後のリリースゲート —— 監査サブシステムを リリースビルドの外に締め出していたもの —— が消えた。

新規

  1. 七つの設定、そして合法な組み合わせはすべてコンパイルされる。 mode、gc、runtime、port、 vm、lms、lspe。成果物レベルの行は、IR だけでなく リンク後のイメージで判定される (17 の判据)。
  2. hosted 層に名前がついた。std は hosted の名前 (libc、ファイルシステム、スレッド、時刻、ネットワーク) を携えてよく、 no_std はそうしてはならない。std + hosted は本物の libc.so.6 をリンクして動き、両方のフロントエンドは no_std + hosted を拒否する。そして IR 自身がその行を宣言するので、リンカは自分が 書いていない主張を検査する。
  3. no_gc は検査される主張である。成果物は「コレクタなし」と 述べ、イメージにコレクタが入っていればリンカはそれを失敗させる。
  4. 安全メモリマネージャが出荷される。七つのレベル —— コンパイル時の検査、 メモリマップ、ガード、拒否器、クラッシャ、プロセス外の再起動器、そして最小限の床 —— があり、既定は lms_full で、設定には四つの段がある。
  5. 監査サブシステムが出荷される。LSPE は七つ目の設定である —— 各判断が何に 支えられているかの台帳、それを必要とする箇所の調査、局所と手続き間のエンジンを持つ義務 システム、そして数えられ、字句的な迂回路としての lspe pass "reason" { … }。 リリースビルドはそれを受け入れる。
  6. ゲートは、何を飛ばすかを言う。既知の赤のリストはスイートではなく判据を 名指しする。予算は基底ブランチに対して検査されるので、変更が床を下げたりスキップを足したり はできない。容量スキャナは木全体のリテラル境界と固定長配列を覆い、ブートストラップの根は 再構築で反証できる来歴の記録を携える。
  7. インタプリタがツールチェインとともに出荷される。T0 から T3、コンパクトな 直列化、キャッシュされた成果物、そして性能の上限 —— そのすべてが記録された台帳に対して 測られる。
  8. 同梱のリンカが、libc の必要とする部分で参照実装と一致する。位置独立 コード、TLS リロケーション、弱いオブジェクトが C の面を閉じ、IFUNC と STT_NOTYPE のインポート、SONAME を持たない共有オブジェクト、 PT_GNU_RELRO がそれを仕上げる。
  9. セキュリティを、振る舞いとして述べる。free は再利用の前に ペイロードを消去する。HTTP リクエストビルダは CR、LF、NUL を拒否する。インストーラは コピーするすべてのファイルを検証し、PowerShell を絶対パスで呼び出す。そしてリリースは SHA256SUMS に対する分離署名を、それが記述するアーカイブの外に公開する。

修正

  1. 自挙コンパイラの内側で互いを上書きしていた状態スロット。 match のアームラベルがコレクタ段のフラグを潰し、エミッタの診断スロットが スレッド生成のフラグを潰した —— それはスレッドの探針で「引数が 20 を超えています」という 偽のエラーとして現れた。どちらも今は自分のスロットを持ち、判据で固定されている。
  2. 拒否する代わりに壊れていた固定表。チェッカの名前環境には上限がなかった (2048 バイト、256 項目) —— 一つの関数に 515 個の let があると Linux では セグメンテーション違反になり、Windows では黙って書き抜けた。今は 4096 項目を持ち、上限で 止まる。エミッタの表にはガードと名前付きの診断が加わった。
  3. 診断に置き換えられたクラッシュ。自挙字句解析器は満杯のトークンバッファを 読み越さなくなり、構文解析器の入れ子の上限は ( [ { と単項連鎖の一回の走査になり、受け入れツールは巨大すぎる入力を切り詰めるのではなく報告する。
  4. 間違ったものを名指していたリンカの失敗。二つのメッセージは、もはや存在 しないゲートをまだ述べていた。入力バッファは 6 MiB に増え、アーカイブ、リロケーション、 インポートの表は広げられるのではなく、直された。
  5. フロントエンドと CLI の沈黙。チェッカの修正六件、ユーザーに見える CLI の 十件、C 翻訳の一巡、そしてレンダラ/リンカの修正十三件 —— そのどれもが、ひとこともなく 入力を失いえた箇所である。
  6. 二つのフォーマッタは、複数行の || 式の中のコメントについて一致する ようになった。判据がコーパスの各ファイルをバイト単位で比べる。
  7. lompi のネットワーク層は internet パッケージである。手作りの HTTP 名は消え、レジストリの索引は帯域外で固定され、取得完了のマーカーはその消費者によって 検査される。
  8. マイルストーンにあるバグ印の 134 のイシューはすべて閉じられた、そして 振る舞いを変えたあらゆる修正は、その前は赤く、後は緑になる判据を携えている。一覧は、 それぞれを名指したイシューとともに マイルストーンのページにある。

この版に無いもの

監査サブシステムはパッケージには入っているが、まだパッケージから切り出されて いない：パッケージングの分割は 0.1.5.1 である。no_std のための完全な 能力連鎖の報告はローダの規則であり、引き続き #536 である。 choose vm は今もコンパイラが出すものを変えない —— インタプリタは走らせる プログラムであり、コンパイラのモードではない。そして監査台帳はまだメモリマネージャのガード 検査を取り込んでいない。その継ぎ目は docs/270 に書かれている。

現在の状態はどこにあるか

このページは履歴である。プロジェクトが今日できることは、サイトの残りとリポジトリに あり、次に何をしようとしているかはロードマップにある —— それは計画として書かれ、 そう述べている。

最新リリース インストールすべきバージョン。つねにこのリンクであり、ページに書き写されたバージョン番号ではない。 ロードマップ 0.1.5 の後に来るもの。機能としてではなく、計画として述べられている。 はじめに インストールして、最初のプログラムを走らせる。 フロントページへ戻る Loment とは何か、そしてそれがビルドする二種類の成果物。
