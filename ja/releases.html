リリース

リリース履歴

最初の Loment から、いま出荷されたものまで。各項目は、そのバージョンが何の ためだったか —— そしてその記録がどこにあるかを述べる。最も初期のものは 別のリポジトリからリリースされており、このリポジトリはそれらのタグを持っていないからである。

ダウンロード はじめに

これはこのサイトで唯一、バージョンを名指しするページである。他のどこでも ダウンロードリンクは releases/latest と言う。ページに書かれたバージョン番号は 賞味期限つきの事実だからである。ここではバージョンこそが主題なので、それらは 名指しされ、それぞれが実際に公開されたものを指し示す。そのいずれも、まだ出荷されて いないバージョンについての約束ではない。

このリポジトリより前

最初の六つのバージョンは、プロジェクトの以前のリポジトリから出た。それらのタグも日付も このリポジトリにはないので、以下に続くのは日付つきの記録ではなく、線の形である —— そしてここでは何もどこにもリンクしない。リンクする先が何もないからである。

0.1.1 —— 最初の Loment

Rust の構文の厳密な部分集合。それは様式ではなく、出発点の制約だった: 言語は Rust がすでに決着させたものによって定義され、だから議論すべきことはごくわずかで、 作るべきコンパイラがあった。もはや部分集合であるとは主張していない —— 重なりは いまもあるが、表層がそれを越えて育ったときにその主張は取り下げられた。

0.1.2 Alpha —— 最初のセルフホスト

言語がそれ自身で書かれ始める。それで得られるものは優雅さではない: 自分がコンパイルする 言語で書かれたコンパイラだけが、その言語が表現できないものを見つけ出す唯一の方法である。

0.1.2 pre1 —— 修復

最初のセルフホストが明らかにした問題。その種のことはプレリリースで起きるものとされている。

0.1.2 pre2 —— いまも立ち続ける基盤

それ以降のあらゆるリリースがその上に建てられているブートストラップの基盤: リポジトリに コミットされた種から自分自身を再構築するコンパイラ、そして再構築された種が始めたときの ものと等しいことの検査。

0.1.3 Alpha —— マルチシンタックスの発想が到来する

別の言語のソースを Loment として読める最初のバージョン。意味はつねにこの言語のものであり、 借りているのは綴りだけである。それは後から足された機能ではなく、プロジェクトの創設の論で あり、だから「ほかに何が違うか」の下ではなくここに挙げられている。

0.1.3.4 Alpha —— 一巡が閉じる

四つの段階 —— 字句解析器、構文解析器、検査器、コード生成器 —— がすべて Loment で 書かれ、その結果は三段階の不動点に到達する。これは以前のリポジトリからリリースされた 最後のバージョンであり、それ以降のあらゆるバージョンが測られる基準である: 言語とコンパイラが、自分たちを定義するのにホストを必要としなくなった リリースである。

このリポジトリから

いま出荷されているものより前に、このリポジトリから出た三つのバージョン。それぞれが節ではなく 一行になっているのは、記録が果たすべき理由からである —— 細部はリンク先のリリースページにあり、 完全なまま育ち続ける履歴はもはや履歴ではなく、アーカイブの二つ目の写しになる。

0.1.4 Pre —— 最初のインストールできる Loment

2026-09-22。プレリリースとして置かれた理由は一つだけである —— 「このリポジトリにはバージョンがある」という主張を、主張ではなく、目で見られる事実に するため。作られ方について一つだけ残っていることがある: タグはアーカイブが構築された commit より前の commit を指しており、GitHub が生成するソースアーカイブはそのビルドの 前の木になる。

0.1.4 —— 使える

2026-09-23。主題は中身を増やすことではなく使えることだった: 構文面はまったく変わらず、作業はインタプリタの最後の部分を経路から外すことに注がれた。 このバージョンの Windows インストーラは、カレントディレクトリを検索しない設定の機械では 何もしない。このバージョンが欲しい場合は zip からインストールすること。

0.1.4.5 —— 回収、そして保証になったランタイム

2026-10-13。四段の回収のはしご。適応型の半分と世代別の半分を伴う。 no_runtime は宣言から保証になった。両方のターゲットでネットワークが動く。 五つ目の次元 vm が、リリースゲートを閉じたまま到来した。同日のパッチは Windows インストーラだけを変えた。

0.1.4.6 —— ゲートが下りる

2026-10-17。すでに作られていながらリリースの外に保たれていた四つのものが、 この版で一度に手の届くところへ来た: コンパイラの隣のインタプリタ層、libc と LibL、そして vm という設定である。残りはこのプロジェクトが経験した最大の欠陥掃討であり、 リポジトリにある issue 番号の多くがそこから来ている。

新規

  1. LVM —— インタプリタ層、T0 から T3。リンカが読むのと同じ中間形式を読むので、 プログラムが二つ目の真実の源を持つことはない。T0 はその形式の四人目の読者だった。T1 は 出力を一バイトも変えずにフィードバックプロファイルを記録する。T2 は命令のデコードを実行 ループの外へ移し、コーパス上で T0 の 6.1×、出力はバイト単位で同一。 コンパクト形式は同じユニットを 375.9 KB から 107.0 KB にする。 T3 はガード付きの特化と脱最適化を加える。このリリースは choose vm を受け入れる —— 0.1.4.5 はリリースビルドでこれを拒否 しており、そのゲートがここで開いた。そうではないこと: インタプリタはリポジトリの tools/lvm.py 一族であり、パッケージはそれを同梱していない。そしてこの設定は コンパイラが出すものをまだ変えない。この一行は宣言であり、保証ではない —— 0.1.4.5 における no_runtime と同じ重みである。
  2. libc と LibL。リリースビルドは本物の libc.so.6 をリンクし、 最後まで動かす。LibL の面 —— fopen/fread/fwrite/ fseek、残りの printf 書式、内蔵ヒープへの綴りとしての malloc/calloc —— は、システムの本物の glibc に対して判定される。 0.1.4.5 の use libl と libc に対する錠は開いた。
  3. スレッド。言語の thread_spawn、そしてシステムコール番号を 覚えるのではなくヘッダから読む os/thread ライブラリ。
  4. 同梱される四つのライブラリ、それぞれ本物の実装に対して判定済み。 os —— 同じ Linux 環境の CPython に対して五つのモジュール。 internet —— 本物のリゾルバとサーバに対して七つのモジュール。
  5. LMS レベル 1 —— コレクタの隣の二つ目のメモリアーキテクチャ: その検査器 （E028/E029）とレベル 3 の入口が、両方の実装にある。
  6. ランタイムを見られるゲート、そして配布。生成されたバイナリを必要とする 104 の判定が、スキップではなく Linux ランナー上でネイティブに走るようになった。走らなかった 判定はもう合格として数えられない。四つのホスト上の読み取り専用ミラー。簡体字中国語の README。VS Code 拡張は Marketplace に載った。

修正

  1. 回収。スイーパは解放されたブロックごとに四つのマークバイトを消さなくなった —— それが生きたブロックをゴミの隣で回収させていた。free は所有を確認し、二重 解放を拒否する。ブロック内部の精度はサイトごとのスロットマスクである。ホワイトリストの システムコールへの引数は借用として数えられる。回収はもうフリーリストを空にしない。回収の トリガはバイトが求められる場所に付き、アロケータが実際に消費する量を数える。再利用された ブロックは記録されたサイズを保つ。昇格したバッファのワードはルート走査に届く。そして L2 の エポックは次の同名の let で止まるので、隣り合う二つのループはもう互いを 妨げない。
  2. かつて沈黙していた、あるいは誤っていた診断。文の先頭の @、 二進リテラル、そして関数の終端に落ちる規則は、参照実装が拒否するのと同じように拒否される。 未知の型は E002 ではなく E030。沈黙・誤り・致命的だった七つの場合が、参照実装と同じことを 言うようになった。同じプログラムがどの表層構文でも同じ数を計算する。use std はもうクラッシュしない。フォーマッタはコメントを保ち、宣言の修飾子を宣言の行に保つ。
  3. エミッタは表現できないものを拒否する。幅の異なる演算、セルフホスト コンパイラの bool != bool、11 個以上の引数、最後のフィールドに末尾カンマが ない構造体、宣言された型に収まらない整数リテラルは、不正な IR ではなくエラーになる。
  4. ランタイムと CLI。配列の添字と算術は検査される。ゼロ除算はメッセージ付きの トラップになる。既定の段の拒否は正しい設定名を挙げる。let x = 1;、 let a: f64、裸の return;、brk に対するコンパイラ 自身のヒープ、250 項の式、400 層の入れ子ブロックは、クラッシュせずに診断される。Windows は ELF ではなく PE を出す。loment check はビルドできないファイルに対して 0 で 終了しなくなった。
  5. リンカ。負の添字は符号拡張される。ミラーリンカは 64 ビットのグローバルと 複数行の case テーブルを読む。

現在の状態はどこにあるか
