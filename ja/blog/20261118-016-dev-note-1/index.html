0.1.6 開発ノート #1

0.1.5.x は閉じ、0.1.6 はロードマップの一行ではなくなった。これはその内側で何が動いているかについての最初のノートで、作業台の隣に立つ人に説明するつもりで書いている。

ノートは瞬間を記録するもので、リリースではない。ここにあるものの一部は参照実装にあり、セルフホスト実装にはまだない。一部はコードのない設計である。どの段落がどれかは明記する。

関数が値になった

関数を変数に入れ、別の関数に渡し、戻り値として返し、その変数を通して呼べる。クロージャは周りの値を捕まえられる。値として、あるいは参照だと明示すれば参照として。値を通した呼び出しは名前で呼ぶのとまったく同じ綴りなので、コードの読み味は変わらない。違いを知っているのはコンパイラだけだ。

これは新しいスイッチ choose fp の後ろにあり、既定では切ってある。切ったままなら、ビルドはバイト単位で以前と同じ。入れると、コンパイラはすべての呼び出し先を見られなくなる。そこで、プログラムがアドレスを取った関数を集め、同じ型の行き先がない間接呼び出しを拒否する。その検査がこの機能の代価であり、はっきり書いてある。

コンパイラが値から型を取れる

let x := e と let x: auto = e は同じ意味になった。ローカルの型は初期化式から来る。最初の版は厳しめの規則を守る。初期化式はどこかで型を綴っていなければならない。変数、引数、フィールドの連鎖、全体のキャスト、あるいは true と false。裸のリテラル、呼び出し、演算子は拒否する。いくつかの組み込みはソースに綴りのない型を返す。片方の実装が推測し、もう片方が拒否すれば、小さな便利が二つのビルドの差になってしまう。この機能は Tur 2026.3 以降のもので、古い版次は答えを変えない。

エラーは起きた場所で扱える

catch はこれまでフォールバック値だけを返した。今はエラーを捕まえて小さな式を走らせることもできる — catch |e| { … } — し、catch return で失敗を早期リターンに変えることもできる。コンパイラにはどちらにも使う switch とペイロードのスロットがもともとあったので、代価は小さく、エラーの道は書いたコードの中に見えたままになる。

クラス：骨組みから本物のディスパッチへ

クラスは、親のフィールドを前に置いた構造体と、メソッド名で名付けられた普通の関数に降りる。単一継承、フィールド、非仮想メソッド、self、構築は参照実装で動く。続いて仮想メソッドが来た。仮想の階層はオブジェクトの先頭に表を持ち、override は固定のスロットを取り、super は親を直接呼び、抽象メソッドは本体のない署名になり、子への参照は親が期待される場所で使える。

境界を二つ、声に出しておく。仮想クラスには runtime が要る。表がアロケータで作られるからだ。セルフホスト実装はまだクラスを読めない。この仕事は参照側である。既定のビルドは変わらない。

エフェクト：実際に走る最初の一片

エフェクト宣言はしばらく前から解析できた。足りなかったのは、それを走らせる半分だ。いま狭い一片がコンパイルできる。腕が一度の resume で終わるハンドラである。降ろし方はインライン化だ。perform は幾つかの束縛と腕の本体になり、handle は自分の本体になる。だからコンパイラの残りはハンドラのノードに会わない。継続オブジェクトはなく、ヒープにも何も確保しない。だからこの一片は no_runtime と手動回収の下でも動く。

その形の外は名前で拒否する。捕まえるハンドラ、中止するハンドラ、二度以上 resume するハンドラ。両方の実装が構文を読める。実行時の降ろしは今のところ参照側だけだ。

プログラムの意味についての第三の意見

この木のほとんどすべての判定は、二つの実装を互いに比べる。食い違いを見つけるのは得意だ。両方が同じように間違っている場合は見つけられない。今年、それが二度起きた。新しい部品は、標準だけから Loment で書いたインタプリタである。コンパイラもリンカもフォーマッタも import しない。小さなプログラムを走らせ、結果を手で書いた期待値と比べる。最初はスカラー、次にループ、break、continue、文字列、構造体を覚えた。すでに二つの版次の間に本物の違いを一つ見つけている。一方は構造体フィールドへの代入を受け入れ、もう一方は拒む。二つの実装が一致しているとき、それは彼らには教えられない種類のことだ。

監査フレームワークは検査の山ではなくなった

コンパイラの検査は、レジストリ、決定的なスケジュール、二層の SDK、そしてそれらを走らせるホストを通る。計画には十四の組み込みがあり、それぞれに段階、ID、飛ばす理由がある。助言だけを出す検査は質問しかできない。証拠を主張する検査は、義務の受け入れ集合を満たさなければならない。外部の証拠を受け入れる義務はまだ一つもない。検査を足すのは登録するだけになった。フレームワークの公開版は、その証拠の面が動きを止めるまでゼロのままだ。

作業台の上の二つの設計

二つはコードのない設計だ。一つ目は借用とドメインを結ぶ。すでに三つのライフタイムがあった。値がどこに住むか、その時間窓がまだ有効か、誰が書いてよいか。どれも互いに話さなかった。新しい規則は借用を時間窓の中に置き、両側に書き込み権限を要求し、法ごとに一本の排他的貸与だけを許す。二つ目はコンパイラ加速器だ。五千行のプログラムは今日およそ二秒かかり、前端と検査器が大半を占める。目標は一秒。第三の実装になり、その IR、ELF、Potato の出力は参照とバイト単位で一致しなければならない。

まだ開いているもの

セルフホスト実装には関数値とエフェクト構文があるが、クラスはない。エフェクトの実行時は狭い一片だけ。合同の借用検査器と加速器は紙の上だ。最初のノートとしては普通のことだ。規則は変わっていない。両方の実装が一致し、ゲートが証明できて初めて機能は完成する。既定のビルドは、新しいスイッチがそれを求めるまで動かない。

次に語る価値のある区切りが来たら、またノートを書く。— Loment Dev Fujo
