Tur 2026.3 第 2 回完全テストビルド：借用ライフタイムと、穴を埋める store

Tur 2026.3 の第 2 回完全テストビルドができました。借用ライフタイムが両実装に入り、 lgc がコレクタに時間軸を与え、store は 332 モジュールに増えました。 プログラムは Loment 自身が持たない便利さを store に求められます。版はまだ開発中です。

これはテストビルドであり、リリースではありません。Tur 2026.3 も未完成です。 安定チャネルは 0.1.5.1 のままです。Playground の Beta チャネルは main に追随します。以下で「次」と書いてあるものは方向であって、日付ではありません。

テストビルドが主張すること

テストビルドは、版全体を一度に組み上げて動かすことです。両方のコンパイラ実装、 両方の成果物経路、そして store 全体。前回のビルドが運んだのはドメインと LSPE で、 ライフタイムは次の行でした。この第 2 ビルドで、借用ライフタイムと拡張された store が 初めて同じ木に入ります。これはチェックポイントであり、タグではありません。

主張は狭く、検証できます。tools/lomentc.py の参照コンパイラと loment/selfhost の自前コンパイラが同じ Tur 2026.3 の面を読み、 コーパスに対して同じ IR を出します。両者が食い違えば、そのビルドは未完成です。

ライフタイム記法なしの借用ライフタイム

&T と &mut T は一次型になりました。引数、戻り値、 構造体フィールド、ジェネリック引数に書けます。次元は choose lifetime_no | lifetime_auto | lifetime_manual です。 tur2026.3 以降は lifetime_auto が既定で、古い版は lifetime_no のままなので、成果物は 1 バイトも変わりません。

表層は静かなままです。借用入力が一つなら、借用出力はすべてそこから借ります。借用入力が 複数で出力が一つなら、最短のものを取るので、 fn min(a: &[u32], b: &[u32]) -> &[u32] に注釈は要りません。 メソッドは self から借ります。戻り値が特定の入力を選ばなければならない ときだけ、-> &a [u32] のように引数名を書きます。借用は成果物では ptr です。スライス借用は既存のビューに正規化され、*r は 参照外し、r.field は自動参照外しです。

自前側は 2026-11-08 に追いつきました。借用型を見ただけで E041 を出すことはもう ありません。E041 は領域が成立しないときだけ出ます。借用引数なしで借用を返す、 存在しない引数に領域印を書く、p が借りられている間に free(p) する、のいずれかです。保存された &mut は後の 借用を E007 で排除します。両側で同じ五つの規則です。

正直な境界。借用をジェネリック引数にすることは参照側だけです。自前側の 登録は名前単位で、let x = &mut y の形だけが排他表に入ります。設計は docs/299。

lgc がコレクタに時計を与える

Tur 2026.3 のもう一つの機能は lgc、コレクタの手動タイミングです。 lgc start(10ms) { … } は協調的な時間予算つきの収集ウィンドウを開き、 lgc start { … } は予算なしのウィンドウを開きます。lgc end; は一時停止、lgc start; は再開です。lgc end { … } は ブロックを出ると前の状態に戻るスコープ付きの一時停止です。

どの choose gc モードでも成り立ち、no_gc と lgc の組み合わせは E039 です。制御するコレクタがないからです。予算が 制限するのは収集の開始であり、実行中の収集を横取りはしません。第 4 の GC 段 ではなく、choose gc が段の選択のままです。

store は 332 モジュールに

Loment は意図的に小さい言語です。store は便利さの置き場です。普通の Loment の ソースで、両実装がコンパイルし、公開名はすべて docs/store-index.md に並びます。現在は 13 パッケージ、332 モジュール、2791 個の公開関数です。 std が 148、残りは os（44）、system（41）、 world（22）、dev（15）、lowlevel（12）、 internet（11）、math（9）、host（8）、 science（6）、baremetal（6）、windows（6）、 engineering（4）です。

直近のまとまりは 5 つの構造的な穴を埋めました。暗号とネットワークには ChaCha20、 Poly1305、AEAD、AES-CTR/GCM、x25519、ed25519、SCM_RIGHTS 付きの AF_UNIX、そして TLS 1.3 クライアントの中核が入りました。合成層にはイベントループ、 原子的なファイル操作、有界 channel、ジョブキュー、小さな HTTP サーバーが入りました。 windows パッケージは Kernel32 の面を宣言します。共有モジュールが os と system 内の重複を置き換えました。生成された索引と タスク別の cookbook で、すべてのファイルを読まずに store を引けます。

store が隠さないもの。TLS モジュールはクライアントの中核で、実 サーバーとの相互運用を主張しません。windows モジュールは PE FFI が 入るまでの宣言面です （#1262）。Loment には 関数ポインタがないため、イベントループは tag で分派し、HTTP サーバーは handler id を 返します。thread_spawn はコンパイル時の関数名を要るので、job queue は キューだけを与え、worker は自分で書きます。

まだ足りないもの

Tur 2026.3 は封じられていません。lifetime_manual は &a T の印を受け付けますが、より広い注釈の面はまだありません。 拡張ドメイン、グラフモデルの実体部分、→ / ≺ / × のドメイン形式、wasm32 バックエンドは設計または後続の作業です。 store のプラットフォームとプロトコルの縁は、埋めるのではなく境界として書かれています。

第 2 テストビルドは、この版を全体として試せる地点です。完成した地点ではありません。
