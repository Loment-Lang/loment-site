これまでで最大の拡張

明白だろう。リポジトリを見ていれば、長い列のプルリクエストに気づいたはずだ。そう —— プロジェクトはこれまでで最大の機能拡張のただ中にいる。0.1.5 より大きい。この二週間で数十の変更がマージされ、十数の変更が開いている。このノートは両方の山を歩く。

ノートは瞬間についてのもので、リリースではない。以下の開いている変更はすべてレビュー中だ。そのままマージされるものもあれば、形を変えるものもあり、生成物の更新が一つある。安定版はまだ 0.1.5.1 だ。

書く量が減った

Tur 2026.3 には今、一揃いの構文がある。最初に来たのは文字列補間だ。f"a{x}b" と rf"..." はフロントエンドで str_concat 呼び出しに書き換えられるので、字句解析器も解析器もコード生成器も新しいノードを知らない。続いて書式指定 —— {x:>8}、{x:<8}、{x:^8}、{x:08} —— と名前付き文字列定数 const NAME: str = "...";。str_num はすべての整数型を受け取る。符号なしも含む。

次は制御フローの便利さだ。if と match 式は let の初期化子全体に置ける。catch |e| { … } と catch return はエラーに二つの形を与える。let x := e と let x: auto = e は初期化子が型を綴っていれば推論する。args(i) はプロセスのコマンドラインを見せる。どれも版次で門番されており、古い版次は同じテキストをこれまで通り拒否し、両方の実装が同じ IR を出す。

関数が値になった

関数ポインタ、クロージャ、間接呼び出しは九番目の次元 choose fp の後ろに着地した。裸の関数名は値であり、クロージャは値で捕まえ、参照を名付ければ参照で捕まえる。値を通した呼び出しは名前で呼ぶのと同じ綴りだ。既定のビルドは一バイトも変わらない。スイッチを入れると、コンパイラはアドレスを取られた関数を集め、同じ型の行き先のない間接呼び出しを拒否する。クロージャのプログラムを両方のリンカで走らせる実行時判定も加わった。

クラスと監査フレームワーク

クラスの梯子はレイアウトからディスパッチへ進んだ。C1 はクラスを、親のフィールドを前に置いた構造体と、通常の関数になったメソッドに降ろした。C2/C3 は vtable、仮想ディスパッチ、super、抽象メソッド、閉世界の行き先検査を加えた。仮想クラスには runtime が要り、セルフホスト実装はまだ追いついている途中だ —— 開いている C4a が非仮想クラスを自ホスト側へ運び、バイト単位で一致する三つのフィクスチャを添える。

その下では、監査フレームワークが本当のフレームワークになった。レジストリ、決定的なスケジュール、二層の SDK、十四の組み込み検査、エンジンごとのスキップ理由と予算。エフェクトのサイトは Potato 台帳に入る。フレームワークの公開版は、証拠の面が凍るまでゼロのままだ。

エフェクト：宣言、そして走る一片

エフェクト宣言はしばらく前から解析されていた。実行時の半分は段階的に来た。lspe_effects_true の後ろの参照フロントエンド、セルフホストの鏡、台帳の E11 サイト、そして末尾再開ハンドラを普通の文へインライン化して実際に走らせる狭い一片。継続オブジェクトはなく、ヒープも使わない。開いている A3b はこの一片を広げる。腕は外側のローカルを読め、return e; で終わる腕は中止する。降ろしはわざと名前を使わない形にして、セルフホスト側が鏡にできるようにしている。それが着地するまで、セルフホスト実装は E0217 を出す。

借用、バッチで

借用システムはパイプラインとして着地してきた。設計は領域、時間窓、書き込み権限を結んだ。検査器は場所をキーにした loan グラフになり、最後の使用が kill 点になった。スライスは構造体フィールドになり、フィールドに格納した &mut は後の借用を排除し、交わらないフィールドは衝突しなくなった。この窓では B1 が着地した。slice_len が &[T; N] を通り、スライス借用に来源マーカーが付く。開いている B2+B3 は次の二バッチを運ぶ —— 呼び出しが返す借用を被呼び出し側の要約から登録し、格納した &mut を一度だけ使い、構造体フィールドからの移動を追跡する。以前の積み重ね版二つは閉じられ、新しいエラー表の上で再着地した。

ドメイン、そして次の安全の物語

ドメインは明示的な兄弟辺を得た。読む人は、宣言された同じ層の組と、偶然隣り合った組を見分けられる。domain:for は空の範囲を拒否し、何も覆わない規則を受け入れなくなった。ドメインと借用の合同検査器の設計が着地した。借用は時間窓の中に収まり、書き込み権限は両側で成り立ち、各法は一つの排他的貸与だけを許す。

開いている研究文書は同じ方向をさらに押す。安全部分集合の中の三つの未検査アクセス —— リテラル配列の範囲外添字、動的スライス添字、生の load8 —— を測り、現在のトラップ経路さえ信号（ud2、SIGILL）だと指摘し、四層、故障 ABI、成果物の中のサイトごとの fault ladder を提案する。

Flomtc：コンパイラの第二エンジン

Flomtc は五千行を一秒未満でコンパイルする設計として始まった。次元と独立した実行ファイルが着地し、開いている変更が最初の本物の最適化だ。prepare の速い道は、ジェネリクスが宣言されていて使われていないとき、モジュール全体の深いコピーを飛ばす。Potato の事実は五回の AST 走査ではなく一回で集め、文字列書き換えには恒等の速い道を置く。対象プログラムの測定で、コールドコンパイルは約 2.1 秒から約 1 秒、ネイティブコンパイラは 15.8 秒から 466 ミリ秒になる。choose flomtc_true の後ろにあり、Potato には記録しない —— 成果物がどう作られたかの話だからだ。

もう一つの研究線は別の問いを立てる。プログラムの起動時の仕事をビルドへ移し、実行時を準備済みの状態から始められるか。それはまだ紙とプローブの上にある。

欠陥の掃除とゲート

開いている一覧は欠陥の山の頂上も片付けている。sev-0 と sev-1 の十四件がすべて閉じられ、七件は現在の main に対して検証された。GC alpha のルート会計が直った。昇格したバッファごとに一つのスタック領域ルートで、語ごとに一つではない。以前は 8 KB で 1024 スロットの表が埋まり、静かに中止していた。エラー報告器の真実の源はセルフホスト側へ移り、メッセージ文を分類する完全な正規表現エンジンを伴う。診断行の一致は缺口ゼロになった。

開いている変更が掃除を続ける。両方のリンカにあった getelementptr の最初の添字のバグ（状態を持つ能力が隣の状態を読んでいた）、PE の openat フラグ意味論、固定されたホットアップデート信頼アンカー、GC 計測ツール、五つのツールバグ、十一の Java フロントドア問題。インフラ側では、CI がシャード負荷下で 330〜420 秒を測ったあと、ゲートの stage1 上限が 900 秒に上がり、シャードが再配分され、開いている変更がマージキューに必要な merge_group トリガーを加える。

新しい版次がレビュー中

開いている変更の一つが次の版次を始める。tur2027.1Alpha、ブロックスコープ付きだ。すべての波括弧ブロックが字句スコープになり、入れ子のブロックは影を作れ、同じブロックの二度目の let は E013、lspe pass、lgc の窓、domain ブロックもスコープになる。専用の GC 検査器と ReclaimScoped 義務も加わる。既定の版次は Tur 2026.3 のままだ。

この山は何になるか

一覧を並べると形は明らかだ。構文の一揃い、関数値、両方のコンパイラのクラス、走るエフェクト、借用の最後の缺口、ドメインの幾何、第二のコンパイルエンジン、欠陥の山の頂上、安全の設計、ゲートの前の行列。この波が 0.1.5 より大きいのは、機能の下の層を同時に作り直しているからだ。そのどれも安定版には入っていない。規則は変わらない。両方の実装が一致し、ゲートが証明できて初めて変更は着地する。既定の成果物は、新しいスイッチか版次が求めたときにだけ動く。

次のノートでは何がマージされたかを書く。— Loment Dev Fujo
