時間の橋

メモリ安全は、真剣に扱うべき問題だ。Loment の開発者は、システムプログラミングで最も難しい問題をさまざまな道から解こうとしてきた。その答えが、LVM と LMS の大きな更新として現れた。これは 0.1.6 の二番目の開発ノートである。

このノートはレビュー中の仕事について書く。取り上げる三つの変更は開いていて、まだマージされていない。安定版はまだ 0.1.5.1 だ。すでに main にある部分はそのように書く。

メモリが題目のすべて

ポインタがオブジェクトより長く生き、添字が境界を越え、世代が検査されず、プログラムは自分のものでないものを読むか書く。この分野はその問題を何十年も抱えてきた。Loment の答えは単一の機構ではなかった。LMS は段階で検査し、能力ドメインは権限を区切り、借用検査器はライフタイムを推論し、GC の梯子は回収を選び、LSPE は結果を監査する。LVM はそのすべてが最終的に走るエンジンだ。

外部の提案 PANGU Ω が七層のアーキテクチャを伴って来た。木と突き合わせると、五層にはすでに対応物があり、本当に欠けていたのは三つだった。その三つは文書になり、文書は下の変更になった。

LMS に fault ABI が生える

ネイティブの g1 オーバーフロー検査は __loment_abort で終わり、それは ud2 に降りる —— SIGILL、終了コード 132、ツールが読めるものは何もない。choose lms_pangu_true の下では __loment_fault(1) を呼び、101 で終わる。他の二種類は 102 と 103 だ。どの故障も fn:blk#idx でサイトを名指しし、LVM 基質が報告する座標と同じだ。センサスがすべての guest の load、store、atomic read-modify-write を歩いて座標を書き留める。セルフホスト実装は同じ故障テキストを出し、シードは再生成され、二つの実装の故障セクションはバイト単位で同じだ。

この仕事から本物のバグが一つ落ちた。IR キャッシュのキーがユーザースイッチをソースダイジェストから外していたので、choose の一行を変えると古い成果物が返ることがあった。修正済みだ。

LVM が機械になる

LVM-A は六つのプリミティブを持つ抽象機械だ。サイト、能力検査、世代検査、故障、チェックポイント、再開。四つの基質で実装できる。sw_cap、sw_tag、hw_cap、hw_tag。最初の一つが着地した。base、limit、generation、alive、kind を持つオブジェクト表。能力は SSA 値、GEP の基、引数、格納されたポインタ、phi、inttoptr を伝わる。すべての guest load と store の前に能力検査が入る。失敗は 101、102、103 で終わり、サイトを名指しする。既定の基質は none なので、普通のプログラムは以前と同じものを出す。

境界も機能と同じだけはっきり書く。アドレスが as u64 で洗われた後は能力が失われる。アドレス再利用後のダングリングはまだ捕まえられない。オブジェクト世代がポインタと一緒に運ばれる必要がある。

両方の解釈器が読めるスナップショット

チェックポイントは内部の詳細だった。今は形式だ。両方の解釈器が同じ LVMC バイト列を書く —— 4 MiB のメモリ、32768 バイトのフレーム、深さ 32 —— そして互いのスナップショットから再開する。プログラムはブロック番号ではなく名前で運ばれる。二つの解析器はブロックの番号の付け方が違うからだ。コマンドラインもスナップショットの一部で、再開時に別のホスト引数を渡せる。

復元のバグが見つかり、直った。ある基底がバイトオフセットで書かれ、ワードオフセットとして読まれていたので、再開後の最初の戻りでオブジェクト表全体が退役した。封印はコンパイラ出力ではなくサイドカーだ。成果物ハッシュ、サイトごとの台帳、保証と仮定を伴う基質プロファイル、ゼロ import 検証器、同じ成果物の創世減衰を運ぶ。schema 2 は両方の解釈器のバイト数と行数の価格、そして予算も運ぶ —— 8000 行、320 KiB、今日の測定は 7,936 行。

故障が読めるようになる

プログラムが死ぬとき、面白い部分はたいてい信号ではない。LVM の故障は安定した最初の行の後に Lomenterr の形のブロックを出す。オブジェクト表の項目、オフセットと越え幅、退役した世代、サイト、助言。llvm.trap も同じ扱いだ。ネイティブ側には段階がある。ptrace 報告器は信号、si_code、アドレス、PC、RSP、任意でソース行を出す。lomelf --fault-report は成果物自身に代替スタックから報告させる。読み書きの方向、アドレス、PC/RSP、サイト、スタックオーバーフローのヒント。セルフホストリンカは同じ ELF をバイト単位で出す。小さな任意の一歩もある。--fault-heal N は 1 MiB 未満の未マップページをゼロマップし、同じ命令に戻る。予算付きで、任意。ページ 0 は既定で致命的のまま。

鏡を作る途中で二つのバグが出た。fn main のエントリが括弧なしの call i32 @main として出され、その経路は一度もコンパイルされていなかった。関数のプロローグでの故障が、前の関数の最後のサイトに帰属することがあった。サイトは今、降ろされたコード長を持ち、検索は半開区間だ。

公証人

監査は、監査者が監査対象の外にいるときだけ価値がある。LNotary は独立した成果物監査器で、Potato だけを読み、ツールチェーンの何も import しない —— コンパイラも、Potato モジュールも、LSPE も。systems 表、GC の梯子、LMS の段階と予算、LSPE 台帳、スイッチの自己整合を確かめる。次元、法則、内容アドレス指定の封印を持つ lawspace サイドカーを導出する。サイト表を検証して封印に結びつける。能力、予算、深さが縮むだけの同じ成果物の派生チェーンも検証する。LVM が有効な成果物でだけ働き、そうでなければ名前で理由を言う。

時間の橋

ここが名前の値打ちのある部分だ。六つのプリミティブはどの基質でも同じ抽象機械だ。封印は、成果物がどの基質向けに作られたかを、保証と仮定とともに記録する。唯一の硬い判定が B5 だ。同じ IR を sw_cap で封印し、hw_cap で封印しても、バイトコードハッシュは同じ。これがハードウェアの世代交代を再コンパイルではなく再封印にする。

現在のシリコンでは、六つのハードウェア原語のうち五つが欠けているか部分的だ。LVM 層は、次の世代を待たずにこの壁を越える方法だ。命令レベルのマーキングは機械の内部で消え、二つの境界検査は壁ではなくコストになり、書き込み権限は命令になり、正確なチェックポイントは実現可能になり、検証不能な ISA の壁は一層下がり、公理は「CPU が解釈器を正しく実行する」になる。信頼の鎖は四つ。バイトコードと封印、LVM-A モデル、二つの解釈器、ホスト ISA。

更新の道

もう一つ、この話に属する開いた変更がある。ホットアップデートはこれまで走っている言語サーバーイメージだけを置き換えていた。bin/ のリンカ、コンパイラ、CLI、ビルドツールはインストールに届かなかった。新しいペイロードはすべてのツールを運ぶ。リリースシード上の投影ツリーから作り、パックして署名する。更新器は生の Ed25519 署名とすべての SHA-512 ダイジェストを、ツールチェーンに同梱された標準ライブラリで検証し、非アクティブな世代を書き、それから current を切り替える。check、rollback、status がある。素の 0.1.5.1 インストールには一度きりのブートストラップが付く。更新器も固定鍵もないからだ。

まだやっていないこと

三つの変更は開いている。sw_tag は参照解釈器にだけある。実装間の再開は双子のフィクスチャでだけ証明され、実ファイル I/O も phi の途中の再開もない。能力の精度はセルフホスト側でアドレスから再構築される。ネイティブ診断は ELF のみで既定では切ってある。Windows PE は後の段階で、レポートは小さなプログラムで成果物が約 3.3 倍になる。修復は Linux の 1 MiB 未満の SIGSEGV/SEGV_MAPERR を予算付きで覆う。既定のビルドは以前と同じものを出す。

2027 年の始まりに、あなたはこの時間の橋を使えるようになる。
