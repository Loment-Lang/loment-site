Loment 0.1.5.2 Beta 2 ya está en el Playground

El compilador de referencia y LVM ya se ejecutan dentro de una pestaña del navegador. Puedes compilar, comprobar, construir imágenes nativas y leer cada forma intermedia que Loment tiene de verdad, sin instalar antes la cadena de herramientas.

Esto es una beta y un canal, no una versión. El Playground ejecuta una instantánea, no una etiqueta nueva; el canal estable sigue en 0.1.5.1.

El compilador se mudó a la pestaña

La página carga Pyodide, una compilación de CPython a WebAssembly, y escribe el compilador de referencia y sus bibliotecas en un sistema de archivos virtual. Una ejecución compila el fuente con tools/lomentc.py y luego ejecuta el IR generado en LVM. No se sube nada: el fuente, la compilación y la salida se quedan en la pestaña. 

module hello fn _start() {    let s: str = "hello from the browser\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

Un programa sellado con _start explícito. Un programa que define fn main() recibe una entrada sintetizada en memoria; el fuente no se reescribe.

Las acciones las define el lenguaje

La lista de acciones es lo que Loment puede exponer de verdad, por eso no hay botones de MIR, HIR ni ensamblador textual. Hay ocho acciones.

Ejecutar y comprobar

Run compila y ejecuta en LVM. Check se detiene tras la carga y la comprobación, así que puedes leer un diagnóstico sin ejecutar nada.

Construir

Produce una imagen nativa mediante lomelf, un ELF para Linux o un PE para Windows, y la ofrece como descarga. La imagen se construye en la pestaña, no en un servidor.

LLVM IR y AST

El IR textual que emite el compilador y el módulo analizado: constantes, estructuras, enumeraciones, capacidades y funciones. Las dos formas que un autor de compiladores lee primero.

Potato y código máquina

El objeto de forma Potato como JSON y el listado hexadecimal de la sección .text del ELF. Potato es el artefacto serializado propio de Loment; el código máquina es lo que el enlazador incluido escribió de verdad.

Wasm

Todavía no está implementado. El botón expone el plan y enlaza al registro de diseño en lugar de fingir que produce un artefacto.

Dos canales, dos preguntas distintas

Beta sigue el último main del compilador de referencia. Hoy se etiqueta como 0.1.5.2.beta.2 y se actualiza automáticamente, así que responde «qué hace el compilador ahora». Stable es el compilador de referencia de la etiqueta v0.1.5.1 y responde «qué hace la cadena de herramientas publicada».

Los dos canales mantienen compiladores, bibliotecas y almacenes de paquetes separados. Cambiar de canal guarda el fuente actual y recarga la página, así que un programa escrito para uno no cambia de significado en silencio bajo el otro.

Lo que todavía no puede hacer

No hay entrada estándar, sistema de archivos ni sockets; LVM solo conoce el descriptor que sintetiza el ejecutor. La ejecución tiene un límite de pasos, así que un bucle que nunca termina se corta y se informa. Los diagnósticos son los mensajes chinos del propio compilador, y la página no los traduce.

El compilador autoalojado no está en el navegador: emite ELF y PE para x86-64, no WebAssembly. El backend wasm32 está diseñado en docs/313 y se sigue en el issue #1496; cuando llegue, el Playground podrá ser impulsado por el compilador escrito en Loment en lugar de por la implementación de referencia en Python.
